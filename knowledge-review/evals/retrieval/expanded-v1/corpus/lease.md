# 队列租约与迟到结果

本文件是公开合成检索协议，仅以本文规则为准，不描述真实部署。每节有独立适用条件；其他文件同名字段不能替代本节证据。

## lease_ms

合成 worker 的 lease_ms=9000 表示取走作业后九秒内拥有执行资格。heartbeat 成功按服务端当前时间续租九秒，而不是把原到期时间再累加九秒。客户端时钟只作诊断，是否过期以服务端时间判断。租约不是 SQL 写锁；worker 计算期间不长期持有数据库事务。

## fence_token

每次重新领取过期作业都会得到更大的 fence_token。发布时必须同时匹配 job_id、active_attempt 和当前 fence_token；旧 worker 即使计算成功也只能记录迟到诊断，不得覆盖新结果。持有旧租约截图不证明当前发布资格，资格由提交事务内重新读取的状态决定。

## 领取上限

claim_limit=3 表示一个 worker 同时领取的未完成作业最多三份。达到上限后不领取第四份，但仍可为已有租约发送心跳。队列中有空位不取消这个限制；claim_limit 不是输出条数上限，也不是每份任务最多尝试三次。

## 租约过期与资格

租约过期只允许调度器重新分配执行资格，不自动标记业务结果为失败，也不创建第二条用户输入。旧 attempt 的日志保留以便追踪；新 attempt 发布成功后作业才进入 succeeded。若调度器尚未重领，旧 worker 仍须续租并取得当前资格才能发布，不能把无人竞争当作有效租约。

## SQL timeout

sql_timeout_ms 是另一套语句诊断值，超过阈值写性能日志。它不是 lease_ms，不会使 worker 自动续租，也不产生 fence_token。 本节独立描述这个辅助功能，名称相似不代表与其他协议具有相同身份、单位或权限。不能用观察值推断未提供的业务条件，未写的配置应视为信息不足。

## 优先级

priority 仅决定待领取作业的排序，数值更大优先。排序不抢占有效租约；高优先级不能绕过旧结果发布时的 fencing 检查。 本节独立描述这个辅助功能，名称相似不代表与其他协议具有相同身份、单位或权限。不能用观察值推断未提供的业务条件，未写的配置应视为信息不足。

## 心跳计数

heartbeat_count 累加成功心跳次数，只作观测。计数高不意味着租约未过期，租约资格必须检查服务端截止时间与 token。 本节独立描述这个辅助功能，名称相似不代表与其他协议具有相同身份、单位或权限。不能用观察值推断未提供的业务条件，未写的配置应视为信息不足。

## 队列深度

queue_depth 包含等待领取的作业，不包含已领取且执行中的作业。它不能推算单个 worker 的 claim_limit 或业务失败比例。 本节独立描述这个辅助功能，名称相似不代表与其他协议具有相同身份、单位或权限。不能用观察值推断未提供的业务条件，未写的配置应视为信息不足。
