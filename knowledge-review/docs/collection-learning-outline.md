# 集合资料生成可审核的知识点与学习目标清单

本文记录清单提取、分层阅读、归组整合、有限定向原文复查，以及 [2026-10-10 前置关系与学习顺序](#前置关系与学习顺序实现2026-10-10)。上述功能已实现；开放式调查、跨清单路线、阶段 C 优化仍为后续计划。保留用户确认的完整后续设计和各阶段记录，各日期章节描述当时范围，以本段和最新实现章节为当前状态。沿用 Python/FastAPI、Markdown、SQLite 和当前兼容模型接口，没有新增模型服务、embedding 路径或依赖。

## 前置关系与学习顺序实现（2026-10-10）

### 用户流程与边界

完成清单和归组核对后，在学习计划中点击“生成学习路线建议”。默认比较这份清单的全部可用目标，也能先勾选部分目标。仍处于“待核对”或“待确认重复”建议中的成员暂不纳入；已确认重复只用代表。未被这类建议标记不代表已经获得语义正确性保证，生成前仍需用户审核候选。路线可以同时包含未加入和已加入计划的候选。

每条关系显示先学/后学目标、类型、理由、依据来源、模型自报的明确/暂定状态及真实原文引用。类型区分“前置依赖”“建议先学”“尚不确定”，依据区分含原文的模型判断和教学顺序偏好。模型自报明确不等于程序证明关系正确。原始模型建议保留；修改方向、类型或理由后当前建议标为用户意见，清除当前引用授权，原模型引用仍可展开查看。可手动添加自己的关系；不伪造原文引用。

“接受关系”只确认建议，不产生题目、作答或复习记录。“跳过关系”保留原建议供查看、再修改；不参与排序和依赖建议。接受时检查有向循环及相同方向的重复关系；循环关系需要修改或跳过才能成为一致的已接受图。待审核图如果存在循环，页面提示并暂用原清单顺序，不关闭任何学习入口。

顺序由稳定拓扑排序提出：先学节点在后学节点之前，其他节点尽量保持原清单顺序。用户能上移、下移、恢复建议顺序；即使自己调整的顺序违反已接受关系，也只显示提示，仍保存并尊重用户顺序。可暂时跳过/恢复目标；这仅改变本路线的推荐范围，不暂停或删除其复习项，不改变 FSRS。

### 一次生成怎样完成

1. 服务校验集合与资料版本、候选固定原文证据、归组审核状态，冻结选中候选完整学习对象及 revision 和相关归组决定。一个 request_id 对应一条路线，同一清单只允许一个 queued/running 路线任务。
2. 为选中目标建立全部无序目标对；跨章节、远处目标同样比较。每次请求含当前目标对的完整知识、条件、能力、标准和固定原文；其余目标仅作为名称/能力导航，导航不授予引用权限。当前回答语言沿用用户选择。
3. 按完整请求的输入预算、输出估计和 Schema 容量决定单批目标对数。模型逐对返回关系或“未提出关系”，代码核对比较身份完全一致，拒绝遗漏/重复/未知目标对及越界引用。“未提出”是该次判断，不保证所有关系已被发现。
4. 任务和判断批次各有 attempt，网络期间不持有数据库写事务。发布前再次检查资料范围、候选/归组版本及任务 attempt，短事务保存回执、关系、实际可见范围、预算，并推进游标。
5. 默认本次最多 24 次逻辑模型请求，可改为 1–200；用完暂停。明确输出截断时缩小工作单元继续，仍计入额度；不保存不完整输出。失败/暂停保留完成判断，继续时增加额度并从游标恢复。最小目标对无法容纳时明确失败，不截断目标或伪造原文。
6. 完成后开放审核与顺序编辑。候选、有效归组决定或当前集合资料版本改变时，旧路线只供查看，不再给出当前推荐；需要重新生成。单纯选择加入计划、延迟绑定知识点 unit 不改变目标语义，不使路线失效。

### 数据为何独立保存

仍使用 practice.sqlite3，新增三个表，不迁移或重建已有学习记录。

| 表 | 保存内容与设计原因 |
| --- | --- |
| `outline_routes` | 清单、幂等 request_id、语言、冻结候选/归组版本、状态、attempt、已比较游标、调用额度、用户顺序和跳过目标、审核 revision。路线可以恢复，修改能检测旧页面；它与学习状态分开。 |
| `outline_route_pages` | 每批准确目标对、原回执、失败状态、预算、实际可见行范围和 attempt。继续复用完成判断；未提出关系和遗漏输出可以区分。 |
| `outline_route_edges` | 原模型建议、当前用户决定、审核状态和 revision。保留证据演变；手动添加的关系没有模型原结果，不冒充资料结论。 |

外部缺失前置话题另存在模型回执中，页面标为“待核实”，不自动创建候选、扩展资料权限或加入计划。没有新增删除接口。

### 下一目标推荐怎样使用真实证据

推荐在读取路线时重新计算，不额外请求模型、不保存掌握百分比、不修改学习数据库。未审核关系仅供顺序预览；推荐使用已接受关系及用户显式顺序，否则从原清单稳定排序。用户暂时跳过、已暂停复习的目标不主动推荐；所有目标的通常加入/学习入口继续可用。

对已加入的候选，读取其固定 target_id 的最近一次首题作答（position=1），关联 effective_evaluation_id 获取**当前有效评分版本**，保留原答案、提示记录、时间、定性评价、反馈与评分来源。评分修订会改变下一次推荐；相关能力目标和追问答案不替代该目标证据。会话进入追问不会使它此前的首题答案失去资格。

“无提示记录＋范围匹配＋可判断”才标为当前本题达标或有缺口；使用提示、已看参考、范围不匹配、评估不确定标为证据不足。未测试标为未知。最近一次使用提示的作答不会被旧达标答案掩盖。已有独立复习事件仍可用于 FSRS 到期建议，即使最新作答证据不足；日期与最新本题证据是不同信号。

当前可解释优先级：未完成的主要作答 → 已有实际 eligible 复习事件且日期到期 → 当前独立作答的定性缺口 → 按路线尝试未测试/证据不足目标。最后一步遇到已接受且尚无当前独立达标证据的前置目标，建议先核对该前置；用户跳过的前置不强制补做。待评分答案不会创建重复练习。各项近期本题都达到标准时允许自由选择新挑战、恢复跳过目标或等待复习，不宣称全面掌握。

未加入的推荐目标只提供定位与审核入口，用户选择加入后才生成首题；已加入的目标可直接开始或继续原有练习。生成、回答及评分后页面刷新证据与推荐，也能手动刷新。暂时没有根据聊天疑惑推导失败复习。

### 预算和实际限制

输入包括系统、当前任务、学习对象、导航、原文、语言、输出 Schema、原生结构化/函数兼容协议与开销；沿用 `GenerationBudget` 的 UTF-8 字节保守估计，预留输出和安全余量，不使用 embedding tokenizer。优先使用显式 LLM_CONTEXT_TOKENS，否则标明应用默认容量未核实。预期输出 `600 + 800 × 目标对数` 是应用启发式，无法保证模型服务实际 token 数或输出完整；最小目标对预期输出空间不足也报错。

当前全目标对比较最坏为平方级，以分批预算和显式额度控制；不是自动优化的大规模图算法，没有跨清单或全部计划的统一路线，也没有可校准的掌握概率。固定原文之外的疑点应通过既有复查/重新提取处理，本阶段没有新增开放式研究工具。原文支持与教学依赖仍须人工核对，条件、同知识不同能力、矛盾与缺失资料可能导致暂定结论。

主要实现：`outline_routes.py` 编排/审核/排序，`outline_route_model.py` 比较契约/预算/引用，`outline_route_store.py` 持久化/恢复，`route_recommendation.py` 读取有效作答证据，`web/static/outline-route.js` 展示与用户操作。`outline_service.py` 和 `web_app.py` 只接入现有清单入口，原按需问答、练习及 FSRS 不由路线接管。验证见 [质量评测](quality-evaluation.md)，实际问题与取舍见 [开发记录](development-log.md)。

## 第一阶段用户流程（2026-10-04）

在“学习计划”中选择计划范围，点击“生成可审核清单”。范围为该集合及子集合的全部当前 Markdown 文件，独立于问答的当前文档和勾选范围。学习方向可选，中文/英语沿用页面当前选项。

章节区显示待分析、部分分析、已分析、失败，以及实际成功分析的行数。没有正文的标题单独说明无需生成。展开章节可查看各段行号、结果说明或失败原因。候选数来自目标原文证据与章节的交集；已加入数来自这些候选的实际加入状态。它们均不表示掌握程度，也不保证模型已经提取了章节中的每个概念。

每个候选包含知识名称、知识说明、能力维度、目标、考察范围、判断标准和原文证据。可修改文字、维度与标准，证据保持不变。修改使用审核版本，避免迟到页面覆盖新内容。勾选目标，选择总知识库或具体集合，再点击加入计划。未勾选内容只保存在清单，不创建题目、复习、失败记录或 mastery 百分比。

加入时按照已审核目标生成第一道练习。练习、稳定目标、复习项和候选加入标记一起提交；用户从该题开始真实作答，然后使用已有评分、原题/变式和 FSRS 流程。可以选择新建知识点或归到当前计划列表中的已有知识点；没有自动语义合并不同候选。

刷新、重启后可选择旧清单；失败可继续未完成章节。暂停会保留已完成结果，正在请求的单段允许完成保存，然后停止。服务中断后通过操作锁确认没有活跃任务，再把中断状态恢复为可继续；尚未开始的排队任务超过 60 秒且无人持锁时视为中断，不自动重复调用模型。

## 数据流与职责

1. 服务端根据永久 document_id 解析集合后代文件，读取 source_id 版本与完整快照。
2. Markdown 解析器建立章节清单：只取最外层标题，支持 Setext，代码块、列表和引用中的标题不算独立章节。父章节记录自身正文，子章节单独记录；前言也计入，每行只归一段。
3. 每章按生成预算切成连续原文窗口，单窗口最多 80 行。预算计算任务、目标、章节信息、原文、语言、SDK 展开的原生输出 Schema，以及兼容结果工具 Schema。两种接口均可容纳后才接收窗口；没有永久截掉尾部。
4. 持久保存清单、章节、窗口和源快照后启动后台顺序分析。每段调用现有结构化接口；每个目标只可引用本段实际发送的原文。程序校验后，将该段的候选与完成状态一起保存。
5. 审核修改保留证据，通过 revision 比较发布。用户选择加入后，首题请求保留目标的全部必要引用，剩余原段资料按整行预算裁剪，引用权限随实际可见范围变化。
6. 模型完成后再次检查集合文件与版本指纹；通过后用同一数据库事务保存首次练习、长期目标、计划和加入标记。复习项是“尚无作答证据”，不会产生 ReviewEvent。

| 模块 | 为什么修改、改变了什么 |
| --- | --- |
| `outline_service.py` | 章节划分、请求预算、逐段分析、引用校验、范围版本检查、审核及首次练习生成集中编排。与按需问答工具流程分开。 |
| `outline_store.py` | 保存可恢复的任务与候选，窗口 attempt 和审核 revision 拒绝迟到结果，OS 锁防重复生成；没有模型调用期间的长写锁。 |

| `web_app.py` | 服务端确定集合范围，提供清单/暂停/继续/审核/加入接口。接口不接受任意磁盘路径。 |

## 失败、并发与资料变化

任务和单目标加入使用数据库旁的 OS 文件锁。锁只限制同一操作，模型调用期间不持有 SQLite 写锁。模型失败或引用校验失败就停在该段，先前候选保留；用户继续时只重试未完成段。单行超过输入预算明确标记未分析，不切造原文；核实并调整生成预算后可重试。协议本身已超预算时不创建不可运行的清单。

单目标重复加入直接返回已有练习/复习项，不再请求模型。首次练习失败或数据库写入失败，候选恢复待审核，事务回滚所有新学习记录。多个目标顺序加入，部分成功会明确显示，余下可重试；整批不是全有或全无的事务。

清单的范围身份取排序后的 document_id / source_id。文件内容、集合成员或子集合变化导致范围变化时，旧清单只供查看，停止继续分析和未加入候选的加入，要求新建当前资料清单。已加入项保留其旧快照，继续使用已有复习逻辑。候选文字修改不扩大原文权限。点击旧版引用仍由阅读器检查版本，不拿新文件同一行冒充旧依据。

章节上下文为自己的正文和标题路径；当前没有跨章节综合分析或全库概念去重，前置关系、学习时长、路线顺序和掌握覆盖评估仍未实现。后台任务由当前服务执行，不是独立队列；中断后的继续需要用户操作。清单/集合删除、归档和自动派生失效清理未提供入口。

## 整体背景与结构切分实现（2026-10-05）

新建网页清单使用自适应阅读流程，旧清单保持原有窗口和候选，可继续原流程。用户仍从所选集合及子集合生成清单，审核选择后才加入。新增“阅读方式与整体背景”区域，显示每份文件的处理方式、选择理由、概述步骤、有效结果、失败及未解决问题。

### 现在一份清单如何生成

1. 服务端固定完整资料快照、范围指纹与章节清单，记录任务语言和学习方向。
2. 按文档选择全文或分层。全文完整请求必须同时容纳两种结构化协议；预期目标数取外层正文块数与 `ceil(UTF-8 字节数 / 500)` 的较大值，至少 1，再按每目标 950 的输出估计比较输出预留，且不得超全文契约最多 6 个候选。这是保守应用启发式，不是 tokenizer 或语义完整性保证。
3. 分层文档按外层 Markdown 段落、列表、表格、代码块边界组成连续原文窗口。沿用最多 80 行及完整请求预算；单个结构超窗时按真实原文行续读，记录续段。空正文不调用模型；单行不能容纳时明确失败，后续原文仍在。
4. 每个原文窗口生成带证据指针的概述；章节内每组最多 4 份概述归并，必要时多层归并，再从章节概述归并文档概览。每次请求重新检查完整预算。归并请求只包含概述及指针，不把指针说成已发送原文，也不强行拼接整个长清单。
5. 局部提取共同收到文档概览、章节概述、派生版本、学习方向、语言和当前原文。按概览与章节概述中的证据顺序补入实际原文，预算不足时限制可选补读范围；这是简单证据补回，不是语义检索或自主复查 Agent。概述不会单独扩大引用权限。
6. 若必要背景与原文窗口合计超预算，缩小当前原文窗口，并在事务中保存完整尾段为待处理；重试不会永久截掉尾部。候选保存本次真实可见范围及请求预算诊断，审核和首题生成都按该范围校验。
7. 全文模式提供全部章节目录和全文原文，在一次有界提取后记录章节处理范围；输入、输出截断或引用错误不发布不完整结果。用户审核、主动加入、首次练习原子保存、评分和 FSRS 继续沿用现有流程。

背景提取/归并每份概述最多 6 个有依据的要点和 4 个未解决问题，内容有长度边界。生成清单采用较短的知识说明、目标、范围与标准 Schema，减少输出压力；局部仍最多 4 个候选，全文最多 6 个。用户之后仍可按原 LearningDraft 契约修改已保存候选。数量/长度有界会损失细节，不承诺完整提取每个概念。

### 为什么增加这些记录

`outline_context.py` 负责模式选择、结构边界、概述树、证据补回和提取组装；`outline_service.py` 保留公开接口、旧流程、审核及加入校验。`outline_store.py` 在原 practice.sqlite3 增加一张 `outline_context_steps` 表，每步记录类型、范围、输入引用/版本、状态、attempt、结果和预算诊断；`learning_outlines.plan_json` 保存处理决策和固定原始窗口；`outline_batches` 增加实际可见范围及请求诊断。这样可复用旧任务和原子加入边界，避免另建执行库后跨库提交。

概述版本由不可变已发布结果的哈希表示，归并保存输入步骤 ID 与哈希。发布检查 attempt、输入版本和当前集合指纹，迟到结果不能覆盖有效状态。网络期间不占数据库写锁，暂停允许在途单步保存后停止。恢复只重试失败/中断步骤，复用有效概述和候选；调整预算后若归并树变化，保留被替代的失败步骤作为记录。原文不被概述替换，不保存隐藏思维链。

覆盖仍按主要提取窗口与章节的交集计算；补读证据不会重复累加处理行数。一个候选可由实际补读的前后章节原文支持，故未独立完成提取的章节也可能出现关联候选；这不表示该章已完整分析。当前概览共享到同一文档的局部提取，没有集合级概念整合或自动合并候选。

## 跨章节归组审核实现（2026-10-07）

这是阶段 B 的第一个可运行步骤。完成章节分析后，用户点击“生成归组建议”，默认比较该清单中全部尚未加入、尚未接受归组的候选；也可以勾选一部分目标比较。范围包含同一清单覆盖的文件与章节，不做跨清单或全历史知识点自动去重。

建议有三种：

- **同一知识点、不同目标**：用户接受后，将来加入的目标共享一个 knowledge unit；解释、应用等目标仍分别拥有 target、ReviewItem 和 FSRS 状态。
- **重复目标、保留代表**：比较能力、考察范围、标准、条件和原文依据。用户选择代表并接受后，只有代表可加入；其他候选继续显示为重复原始记录，保留 ID、原文及章节关联。不同 capability 的候选不能通过重复目标校验。
- **条件或证据待核对**：不能接受为归组，可以保留独立。B1 不自动调用资料工具调查疑点，后续再实现有限原文复查。

模型建议可修改名称、说明、重复目标代表及可选已有知识点。接受建议不创建首题、知识点、复习项或 ReviewEvent；仍需勾选目标，选择总知识库或具体集合，点击加入计划。接受的归组可撤销，既有题目、目标 ID 和调度不会迁移或重建。候选文字仍可审核修改，固定引用不变；修改候选会使相关待审核/已接受建议失效，已加入目标保持原状。归组之间可能是重叠的备选建议，程序阻止同时接受含同一候选的两组；尚未实现组内嵌套重复目标的自动组合。

### 请求与数据流

1. 服务端确认清单已分析完成、当前集合/文件版本匹配，解析候选 ID 与 revision，保存归组任务输入；同一个 request_id 返回同一任务。同一清单只允许一个 queued/running 归组任务。
2. 组装完整候选知识说明、能力、目标范围和判断标准，从该清单的原文快照补回每条引用原文。先核对引用位于原提取请求的实际可见范围；没有看到的原文不能因文件存在而获得权限。候选、学习方向、证据作为数据，语言沿用当前中文/英语选择。
3. 检查包含任务、全部候选及必要证据、偏好、模型参数、原生 Schema/兼容工具 Schema 和协议开销的完整请求。模型比较语义、条件与目标，不用标题相似度或关键词直接合并。
4. 请求期间只持任务 OS 锁，不持数据库写锁。返回后核对当前资料指纹；发布事务再核对输入候选 revision、状态和已确认归组，检查 attempt 后一次保存完整建议。非法身份、不同能力的重复目标、重复输出或过期结果整份拒绝，不保存半份建议。
5. 用户审核采用 revision 校验与短事务，检查候选仍待加入、未被另一组接受。重复提交相同决定返回已有版本。模型原建议独立保存，当前用户修改及决定另存；本版没有逐次审核历史的回滚页面。
6. 加入目标时保存归组 ID/revision。首题返回后的单一事务再次确认归组未改变，首次需要时创建并绑定统一知识点，再保存首题、独立目标、ReviewItem 及候选加入标记。并发目标按数据库事务串行绑定到同一 unit。任一步失败均回滚，包括新建的 unit；在途期间撤销/修改归组也会拒绝旧首题结果。

### 为什么新增两张表

`outline_group_runs` 保存清单、幂等请求标识、语言、资料范围、输入候选内容与版本、任务状态、attempt、错误、比较说明和完整请求预算诊断。它描述一次比较，失败可重试，输入被修改则需要新任务。`outline_groups` 保存对应任务、成员 ID/revision、原始模型建议、最新用户编辑、决定、审核 revision 及延迟绑定的 unit_id。成员合法性由程序在生成、审核及加入边界检查；没有新增删除入口。

原有 `outline_candidates` 不被替换。知识点名称采用确认后的归组名称；新 unit 的知识说明以首次加入候选为基础，B1 没有生成一份综合知识正文。各 target 的 `source_knowledge_json`、首题资料快照及判断标准仍来自各自候选，而非用其他成员证据冒充自己的依据。选择已有 unit 时不改写其内容或原 FSRS，只追加用户选择的独立目标。

模块变化：`outline_grouping.py` 负责模型契约、证据组装、完整预算及迟到发布检查；`outline_group_store.py` 负责任务、建议、审核、幂等、恢复与统一 unit 绑定；`outline_store.py` 在候选修改和加入事务中接入归组检查；`outline_service.py` 返回归组状态和重复候选禁选状态；`web_app.py` 提供生成/重试/审核接口；`web/static/outlines.js` 提供修改、接受、保留独立、选择代表与证据跳转，轮询保留未保存表单。

### 预算、恢复及边界

沿用生成端保守 UTF-8 字节估计，预留输出和余量；没有调用 embedding tokenizer。模型真实容量未核实的 fallback 会明确标注。B1 当时是一次有界比较，超预算需缩小范围；最多 4 个建议、每组 8 个成员，不代表全部关系已发现。2026-10-09 已补自动分层、跨批关系步骤和原文核验，见本文末节；语义完整性评测仍需扩展。

失败不覆盖其他有效建议。重试只针对该任务且要求输入版本仍匹配；完成任务重放不会重复调用模型或插入建议。刷新/重启恢复任务、审核和加入结果；无人持 OS 锁的 running 任务或超过 60 秒的 queued 任务标记为中断，用户决定是否重试，不自动付费调用。归组生成未新增独立队列、暂停按钮或删除接口。候选范围改变时旧清单仅供查看；撤销审核允许保留原记录，不能恢复使用旧资料继续加入。

### 处理方式与预算选择

以每份文档为基础选择方式，集合允许混合处理。决策记录包括资料版本、预算配置、输入估计、预期输出规模和选择原因；文件字节数、页数或章节数只能作辅助信息。

| 条件 | 建议方式 | 需要检查的限制 |
| --- | --- | --- |
| 内容连贯，全文输入及预期清单输出均有预算空间 | 全文提取，再检查章节覆盖和明显遗漏 | 容量足够仍可能遗漏；需真实样例验证 |
| 全文或清单输出超预算，或章节关联需要逐层梳理 | 章节概述 → 文档概览 → 局部提取 → 分层整合 | 每个概述、整合及复查请求都独立检查预算 |
| 章节可独立处理，且实测顺序调用耗时成为瓶颈 | 在共享背景下有限并发提取，再集中整合 | 服务限流、总调用数、费用及一致的资料版本 |
| 子任务需要独立角色自主选工具、调查或交叉审核 | 后续评估多 Agent | 必须证明质量或效率收益，不能只依据文件大 |

完整请求预算包括系统任务、用户方向、语言、目录及概览、当前原文、候选数据、工具定义与结果、输出 Schema、请求选项及协议开销，并预留输出空间和估计余量。继续采用经核实的模型配置优先、无法精确计数时明确标注保守估计的原则；不使用 embedding tokenizer 代替生成 tokenizer，也不假定模型名称对应固定容量。现有预算边界见 [生成请求预算](document-rag-and-token-budget.md)。

输出规模是独立约束：知识点、目标、判断标准和引用都占空间。未来全文模式需设计有界输出契约；预计清单太长时改为按章节或主题处理，结果分页持久保存。输出截断应作为失败或不完整结果处理，不能因请求放得下就把少量返回项当作完整清单。

### 分层数据流与上下文

1. **固定范围与快照。** 沿用服务端解析集合及子集合、`document_id/source_id` 指纹、完整原文及章节清单。选择集合不扩大聊天资料权限。
2. **建立章节概述。** 从原文逐段提炼章节主题、术语、条件、例子、关联与疑点，保留原文证据指针。大章节先生成局部概述再归并；空正文标题仍由程序处理。第一轮不能声称已经阅读未发送的大文件全文。
3. **建立文档概览。** 从章节概述逐层汇总文档目标、主要概念和章节关系。概述总量过大时继续分组归并，不能把所有概述强行拼进一次请求。目录是导航信息，不是正文知识证据。
4. **提取局部候选。** 提供“学习方向与语言＋文档概览＋章节背景＋相关定义＋当前原文”。概览与定义保留来源指针；需要据此生成知识点时，补读相应原文后才能建立引用。每次生成的引用权限仅包含实际发送的原文范围。
5. **逐层整合。** 先章内，再跨章节或主题，最后集合层面归并。保留合并前候选和稳定 ID，通过关联记录说明哪些候选支持新结果；大候选集分组处理，不能因最终请求超预算静默丢弃尾部。
6. **定向复查。** 对重复、冲突、前置关系或证据不足的疑点，读取限定原文范围，重新核对后给出建议。限制复查轮数、调用预算和费用，耗尽时保留未解决项，供用户查看或继续。
7. **用户审核与加入。** 展示知识点、目标、证据、覆盖记录、合并理由和学习顺序建议。用户修改、选择目标及目标集合，随后沿用首题生成与原子加入流程；未选择项不创建题目、复习事件或掌握状态。

概述和历史助手解释均作为待分析数据，不能提升为系统指令或冒充文档原文。模型负责内容分析与建议，代码负责状态、预算、版本、可见范围和引用校验。回答语言继续使用当前中文/英语选择；恢复任务时保留任务保存的语言偏好。

### 切分、证据与整合规则

切分优先遵循章节、段落、列表、表格和代码块边界，再按生成预算调整。超长结构确需拆分时标注续段与必要背景，保留精确原文行号；必要的背景重叠不重复计算分析覆盖。不可容纳的内容明确报告，不裁造原文，也不改写源快照来适配预算。

概述是有损派生结果，应保存版本、覆盖范围、来源指针和未解决问题。原文永久保留在该清单快照中，概述不替换原文；概述中的事实只有补回实际原文后才获得引用权限。裁剪资料后同步缩小可引用范围，不能跨未发送空隙引用。

合并需比较知识含义、适用条件和证据，相同术语不能直接判定为同一知识点。同一知识点可以有解释、应用等不同目标；不同条件下的结论与相互矛盾的说法分别保留。无法确定的合并作为可拒绝建议，不直接修改已有学习记录或 FSRS 状态。

前置关系及学习顺序也属于建议，展示依据与不确定性，不锁关、不推断用户不会。资料未覆盖的前置知识只能标记为待补充建议，由用户决定是否纳入；不得伪造文档依据。本轮规划不承诺学习时长预测、自动教材编排或掌握百分比。

### 覆盖、审核与持久恢复

前端分别显示：原文处理范围、候选知识及目标分布、用户已加入目标。分析进度与待复查疑点单独呈现；不把分析完成等同于知识完整或用户掌握。全文模式同样需要章节清单，便于发现只有部分章节产生结果的情况。

沿用现有三张表与事务边界；实施时按实际阶段增加概述、整合和复查记录，不预建大量未使用的框架。派生结果至少可追溯到清单、资料版本、覆盖行范围、输入概述/候选 ID 与版本、阶段状态及 attempt。保留原始候选及用户审核内容，整合结果另存版本，避免覆盖审阅依据。

模型调用期间不长期持有写锁。发布前检查资料指纹、输入派生版本及 attempt，过期结果不得覆盖新状态。概述、整合或复查失败时保留此前有效结果和原文，仅重试失败及依赖失效的步骤；暂停、服务中断和并发恢复沿用明确的操作锁与版本检查。

范围变化时，旧任务保留供查看，阻止继续发布或加入旧候选，要求针对当前资料重建。已加入项继续保留旧快照及既有调度。重复执行、并发加入和任务重放仍由业务幂等与数据库事务保证，不依赖模型或框架“恰好只执行一次”。本方案没有新增删除入口；完整删除失效链路仍为后续交付。

### LangChain、LangGraph 与多 Agent 的引入条件

第一步使用现有 SDK、FastAPI、Pydantic、SQLite 和 Python 编排实现分层流程。它们已经承担模型调用、接口、契约和存储；自行实现的部分主要是业务流程。这样便于直接观察按需检索、实际发送范围、结构化兼容和事务行为，代价是需要自行维护重试、恢复、执行记录和测试。框架同样可以实现这些边界，并不天然更慢或更不可靠。

| 选择 | 在本项目中的作用 | 何时评估 |
| --- | --- | --- |
| 现有 Python 流程 | 明确的顺序阶段、预算检查、业务事务；独立任务可有限并发 | 作为下一阶段默认方案 |
| LangChain | 复用模型、工具与集成的适配及上下文组织能力 | 服务和工具种类增加，维护适配的成本有实测依据时 |
| LangGraph | 表达状态节点、分支、复查循环、并行、检查点及人工暂停恢复 | 整合—复查—修订等流程明显复杂，现有编排难维护时 |
| 多 Agent | 为自主调查、专门审核等角色提供独立上下文与工具决策 | 单一流程在特定任务上存在可证明的质量或效率瓶颈时 |

大文件分层处理不自动需要多 Agent；多次模型调用或并行章节处理本身也不代表多 Agent。引入独立角色后仍需共享概览、固定资料权限、原文证据和集中整合，隔离上下文不会自动获得整体理解。

如需 LangGraph，先在清单流程做小范围试点，节点可继续调用现有 SDK 与业务服务。图检查点只负责执行恢复，SQLite 仍负责审核、目标、计划及复习事件的业务事实，避免两套互相冲突的状态。检查点重放不能替代加入幂等和原子事务。暂不安装框架、切换模型服务或重写问答与复习链路。

### 分阶段交付与验收

| 顺序 | 交付内容 | 核心验收 |
| --- | --- | --- |
| A：整体背景与结构切分 | 章节概述、文档概览、带背景的局部提取、预算路由与完整记录 | 前章定义、后章使用的样例可正确关联；小文件全文及大文件分层均有完整请求预算；原文及引用范围不变造 |
| B1：归组审核（已实现） | 同知识不同目标、重复目标代表、待核对建议；保留原候选与证据，用户确认后选择加入 | 相同知识共享 unit，不同目标各自 FSRS；重复只加入代表；失败、并发和过期审核不新增学习记录 |
| B：整合与定向复查 | 可追溯的合并建议、冲突和前置关系、有限复查、审核学习顺序 | 重复可归组，条件差异和冲突保留；合并可拒绝；恢复与重复加入不丢结果、不重复生成学习记录 |
| C：根据评测优化 | 先评估有限并发，再按需要试点框架或多 Agent | 对同一批资料比较质量、耗时和费用，有可说明的收益及代价再引入 |

评测资料至少包含小型连贯笔记、跨章定义与例子的大文件、同术语不同条件、相互矛盾的多文件、长表格/代码块以及输出过大的知识清单。人工标注一组应提取知识及证据，用于比较遗漏、重复、条件准确性和引用正确率；同时记录调用数、耗时、预算估计与费用（服务返回实际用量时另存实际值），不把估计费用当作账单。

受控接口测试验证预算、可见范围、事务、过期发布、失败恢复及审核状态；真实模型样例验证关联理解和整合效果，两者分别报告。每阶段回归一般聊天零工具调用、文档/集合练习、语义评分、主动加入和 FSRS 修订。验收通过也只说明测试资料范围内的表现，不宣称任意整库知识完整性。

### 质量评测第一步已实现（2026-10-08）

新增版本化合成样例与独立评测入口，直接调用现有提取、归组和评分服务，记录完整预算、耗时、失败/部分结果及草案一致性；真实提取通过人工模板匹配参考点并审核条件和证据。没有自动语义裁判，草案标注尚待用户确认。归组使用固定候选单独评测，便于定位提取遗漏与关系错误；覆盖进度仍不是知识召回率。

## 大候选集自动分层整合实现（2026-10-09）

### 路由与完整预算

`outline_group_plan.make_plan()` 对完整所选候选、固定引用原文、方向、语言、系统任务、Schema 及协议计算输入预算，同时检查估计输出和单次契约容量。输入/输出都可容纳才直接比较；否则按章节和预算建立叶节点及稳定二叉上层节点。不是按文件字节数决定。单次最多 8 个成员、64 个比较身份是当前接口的表达边界，记录为 contract_fits；不声称这是模型上下文容量。路由保存 input_fits / estimated_output_fits / contract_fits、估计方式与原因。

输入继续使用 GenerationBudget：模型配置的上下文、输出预留和安全余量，无法精确计数时用明确标注的 UTF-8 字节与协议余量估计，检查原生和兼容提交协议。输出估计为 `400 + Σ(2 × ID UTF-8 字节 + 600) + 16 × 比较数`，是应用启发式，不是准确 token 或预言模型会返回多少关系；回执和续处理用来发现实际未完成工作。最小两项候选和必要证据仍不能容纳时明确报错，保留输入，不静默裁剪条件或原文。

### 分层比较、回执及原文核验

1. 固定候选 ID/revision、资料快照与范围。章节内有界比较直接发送各候选已有引用原文。
2. 上层比较两个子节点的候选卡片。卡片保留完整 knowledge/target、条件、能力、标准及证据指针，只去除 original_evidence；不额外调用摘要模型压缩目标条件。独立候选也进入上层，所有候选对分配给叶节点或最低共同祖先，避免只扫描相邻批次。
3. `ComparisonPage` 沿用三种建议和原输出限制，增加已处理/待处理身份。程序核对每个请求身份恰好出现一次；未知、遗漏、重复、将未完成对写为建议均拒绝。建议满 4 个槽位时，未报告关系的比较重新进入待处理，防止输出容量隐藏额外关系。
4. 上层返回的关联仅作为导航假设，优先补回固定原文核验；模型可否定或改成待核对。每次核验请求重新预算，持久诊断只记录实际发送证据范围。卡片指针不授予原文引用权限。当前只核验候选已有证据，没有模型自主调查其他原文的工具循环。
5. 未处理回执或明确输出截断时缩小比较页并继续。其他解析/校验/服务失败保留错误，不猜成输出不足。单对比较仍无法完成时停止，避免无限循环。
6. 从原文核验关系组装最终建议；扩入成员要求与组内每个成员都有同类型支持，待核对关系阻止确定合并。A–B、B–C 不证明 A–C。可形成超过单次 8 成员的审核组；也可能有重叠备选组，不能同时接受冲突分组。展示理由为有界摘录加程序依据，完整模型结果及支持步骤保持存档。
7. 全部计划比较与筛选关联的必要核验完成后，在短事务发布建议。候选及学习记录不被自动修改，仍经现有审核、选择和首题生成事务加入。

这里的“分层”是可追溯的比较范围树，不是逐层生成有损语义摘要，也不自动合并中间节点。最坏候选对工作量 `N(N−1)/2`；第一版优先保证未归组项、远处项不会被程序过滤掉，代价是规模增长时请求多。卡片的否定判断仍可能漏掉真实关系，已处理回执表示模型报告完成指定比较，不是知识召回率或语义完备证明。

## 有限定向原文复查实现（2026-10-09）

本次是在归组完成之后，对 `needs_review` 建立独立复查任务。与已有 `verify` 的区别是：verify 只补回候选已有引用；复查可以读取这份清单保存的集合资料快照中尚未引用的邻近说明、定义或条件。没有扩大问答资料权限、跨清单或跨聊天范围，也没有加入语义检索与 embedding。

### 一条复查如何运行

1. 网页生成或继续归组时，后台先完成原整合，再依次为当前待审核的不确定建议考虑复查。旧建议可手动点击“定向补读原文”。每个建议同一时刻只有一个有效排队/运行/暂停任务；同一 request_id 返回原任务。
2. `start_source_review()` 固定建议 revision、完整候选及其 revision、语言和范围指纹；原候选固定引用仍使用现有契约校验。资料取自 `snapshots_json`，无需读取浏览器提交的路径。
3. `run_source_review()` 持父整合任务的 OS 锁，短事务领取任务/步骤。调用模型前立即占用父任务的一次逻辑请求额度；网络期间没有 SQLite 写锁。
4. 模型看到完整原候选、原建议、学习方向、当前任务语言、来源目录、预算允许的章节导航、实际引用原文，以及此前完成的补读结果。章节和定位指针是导航，不是知识证据。材料中的指令作为数据处理。
5. 模型可请求按行读取，或用字面短语在许可快照内定位。每轮最多两项，最多两轮，包括只定位而未读取的轮次。定位最多返回六个来源/行号指针，不返回原文、不授予引用权限；之后实际读取才能引用。查询未命中不证明整个集合没有答案。
6. 读取先扩展至完整外层 Markdown 块，然后在完整块边界上按预算缩小；单次请求及实际返回最多 200 行。不从中间截断表格/代码/段落，最小块无法容纳时明确失败，原始存档不变。相同已完成请求复用结果；裁剪后只能引用实际发送范围。
7. 每次决策、加入新原文与定位元数据之后，都重新检查原生 response_format 和兼容结果工具两种完整协议的预算。必需候选、原引用及实际补读证据不静默截断；章节导航是可选内容。沿用生成预算的输入估计、输出预留、安全余量和模型配置来源标签。不是生成模型 tokenizer 的精确计数，兼容探测/SDK 重试也不等于一次逻辑请求恰好一次 HTTP。
8. 两轮之后使用只允许 `conclude` 的接口 Schema，不再执行第三轮读取。模型可以提前结束。最终结果分为同知识不同目标、重复目标、保留独立、仍未解决、需要修订候选；后三者不会被当作自动合并。补读动作可附带可见说明和暂时未解决状态，但只有 conclude 发布最终结果；不保存隐藏思维链。
9. 发布逐步骤及最终结果前重新校验当前资料范围、候选/建议版本和执行 attempt。暂停立即撤销在途发布权限。失败保留输入和已完成补读；继续只请求未完成步骤，不重复已有补读，不产生学习记录。

### 为什么使用独立任务和结果

`outline_reviews` 保存每项不确定建议的任务、固定输入、结果、状态和采用后的 group_id；`outline_review_steps` 保存每次真实模型动作、实际补读/定位观察、可见行范围、预算及 attempt。与原建议、原整合步骤分开，能解释“最初为什么待核对，后来补读了什么，用户采用了什么”，也能恢复中断，而不把新解释覆盖成原模型结果。

共同额度保留在 `outline_group_runs`，避免每个新疑点都悄悄获得一份额外免费额度。首次自动调查最多使用原任务剩余额度；用完暂停，用户填写额度并点击继续，按已用次数增加额度。一次正常完整调查最多三次逻辑请求：两轮读取决策加一次最终结论；失败后的用户显式重试会另外计费，不自动无限重试。

用户采用同知识/重复结论时，原建议标为被取代并保留，另建 accepted 建议并链接复查结果；用户仍可选择重复代表及已有知识点。采用“独立”只将原建议拒绝并记录采用关系。两者都不创建知识、题目或复习项；仍需用户勾选加入，沿用现有首题事务、统一知识点延迟绑定和独立 FSRS。新结论中引用的补充证据不替换原候选引用，不会自动改写其知识说明或目标。

未解决结论可以带非绑定的修订建议；明确修订结论必须有建议。二者均不可采用成归组决定；只有正向结论才能进入采用入口，不能附带需要先修正候选的条件。候选/建议修改后，旧任务失效；暂停旧任务也会释放活跃任务唯一约束，允许当前版本重新复查。当前没有自动更换候选证据入口，需要扩大候选证据时应重新生成清单。

复查针对保存建议的完整成员集合，不重新输出任意子集；原文比较页的八成员输出限制不用于已整合大组。完整输入放不下时明确失败，不能用遗漏候选的结果替代大组结论。

### 接口与验证

- POST `/api/outline-groups/{id}/source-reviews`：幂等启动，语言沿用当前选择。
- POST `/api/outline-source-reviews/{id}/continue`：显式增加共同额度，复用完成步骤。
- POST `/api/outline-source-reviews/{id}/pause`：立即使在途结果失效。
- POST `/api/outline-source-reviews/{id}/apply`：校验建议版本，采用可用结论；重复请求不创建第二个分组。
- GET 清单公开结果包含复查状态、过程、实际原文依据、最终结论和失效/采用标记；正在复查时页面持续更新。

专项受控测试见 `test_outline_review.py`；独立合成评测见 `quality_source_review.py`，默认 smoke，显式 live 才请求现有模型。报告和真实失败见 `quality-evaluation.md`；实际遇到的问题及方法选择见 `development-log.md`。复查不是全库事实裁判：字面定位可能漏同义改写；目录超预算、不可分大块、输出截断或服务未提交结果都可能导致失败；复杂冲突仍交由用户审核。开放式调查、学习前置关系/顺序、跨清单去重、自动候选证据修正及真实大库质量评测仍为后续。
