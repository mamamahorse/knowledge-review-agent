## 样例及标注

`evals/suite.json` 保存版本、Markdown 文件哈希、应提取参考点及原文指针、固定候选关系、固定作答和复核事项。2026-10-09-v2 为八个文件组成七组资料，均为本项目编写的合成教学材料；不读取私人笔记或聊天。边界条件以样例自己的约定为准，不把教学简化当成完整协议说明。

| case ID | 要检查的问题 |
| --- | --- |
| `small_tcp` | ACK 含义与纯数据计算，解释和应用维度分别保留 |
| `cross_chapter` | 前章定义与后章使用、零长度、控制标志、缺口；分层流程 |
| `same_term_conditions` | 数据窗口与界面窗口同名，但条件和知识不同 |
| `conflicting_files` | TTL 10/30 冲突，没有版本依据时不能自行消解 |
| `markdown_structures` | 表格、代码、伪标题、原文连续范围以及资料中的伪指令 |
| `duplicate_targets` | 同目标不同章节的重复，相关协议字段不能直接视为同知识 |
| `large_candidates` | 12 个固定候选跨远处章节；RST 三对原文支持、ACK 不同维度、窗口区别、TTL 冲突及独立项参与 |

四组评分来自固定题目：等价表达、字节序号错误、遗漏条件、答案中的伪指令。遗漏条件允许两种整体判断，因为题设已给条件，“是否必须重新叙述”需要人工讨论；逐标准分类和整体判断分别比较，不能用 rubric 计数决定等级。

所有参考标为 `draft_reference_human_review_needed`：开发时编写，尚待用户人工确认，不是专家金标准。修改资料必须核对所有行号与参考、更新文件哈希和 revision；离线校验会拒绝旧哈希、越界指针和未知身份。

达到调用上限时保留已完成部分，后续阶段标未执行，分层步骤失败留在专用库。评测命令当前没有续跑旧运行入口；可再运行获得新记录。正式产品清单的续跑机制保持不变。

## 报告如何阅读与审核

报告分三层：程序校验（合法身份、实际可见引用、完整请求预算、状态）；与草案参考比较（固定候选对和固定作答）；人工语义复核（真实提取是否遗漏、条件是否正确、证据是否支持结论）。原文已处理行数不等于知识召回，模型请求返回也不等于业务校验通过；调用状态 `returned` 之后仍可能有候选发布失败。

报告包含模型名、样例指纹、关键代码哈希、实际候选/条件/判断标准/原文、逐任务耗时和预算。归组的 integration 记录计划、输入/输出路由、步骤输入、回执、原文可见范围和核验进度；卡片处理量不表示全文证据已核验。预算沿用生成端保守 UTF-8 字节估计，包含原生及兼容 Schema 的完整协议，预留输出和余量，不使用 E5 tokenizer。当前没有保存服务实际账单用量，不能据估计宣称精确费用。

复制本次 `review-template.json` 为 `review.json`，填写审核人/方式。对每个参考点选择 `matched/missing/unreviewed`；matched 填实际候选 ID，支持一个参考点对应多个候选。逐候选审核 `acceptable`、`conditions_correct`、`evidence_supports_claim` 为 true/false/null，可填写说明；真正重复的实际候选 ID 放入 `duplicate_sets`，同一成员不能出现在多个重复集合。

```powershell
.venv\Scripts\python.exe quality_eval.py review .data\evaluations\<运行目录> .data\evaluations\<运行目录>\review.json
```

输出 `reviewed.json` / `reviewed.md`。结果指纹不同、身份未知、遗漏或重复审核会拒绝，不能套用旧运行的审核。完整真实提取、全部参考点已审核后才计算参考点召回率；完整真实提取、所有候选接受性已审核后才计算候选精确率。分母仅是本样例草案参考，不是全知识库。未完成、未审核和 smoke 不显示语义比率，null 不是零分。条件错误、缺少语义依据和额外重复候选另外记录，不合成任意质量总分。
