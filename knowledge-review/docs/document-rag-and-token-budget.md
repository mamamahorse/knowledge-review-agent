# 文档问答与 token 预算

## 为什么修改

之前网页强制选段，限制文档级提问。字符分块也只是软上限：不可分的段落、代码块、标题加上输入前缀可能超过 embedding 模型限制，导致整次搜索失败。报错中的 540 tokens 是文档索引片段超限，并非浏览器选择文字的直接长度限制。修复期间曾加入每次问答都先搜索的分支；用户随后明确要求按证据需要由 Agent 决定是否调用工具，该强制分支现已删除。

## 当前问答流程

```text
打开当前文档 → 提交问题（选段可选）
→ 后端校验文档 ID、资料版本与可选行号
→ Agent 接收问题、允许访问的文档目录与可选焦点原文
→ 模型判断已有证据是否足够、是否需要查阅资料
   ├─ 已有证据足够或一般对话：结束资料收集
   ├─ 缺少资料证据：调用 search_notes 或 read_source
   └─ 查阅后仍缺少上下文：继续搜索、改写查询或读取
→ 结构化回答 + 实际可见范围内的引用校验
```

当前整篇文档与额外勾选文档是工具的允许访问范围。初始文档目录只有文件名、版本 ID 和行数，模型尚未看到这些文档的全文；可选焦点与前后至多五行则是真实可见证据。已有资料足够时可以直接回答，缺少证据时模型决定搜索、读取或补查。目录元数据不能作为内容证据。

网页与 CLI 的 Agent 都使用 `tool_choice="auto"`，没有 `initial_search` 分支，也没有在零次工具调用后偷偷补一次搜索。只有模型调用 `search_notes()` 时才加载本地 embedding、按 token 自动分块和建立/复用向量索引；`read_source()` 可直接读取原文而不运行 embedding。工具失败沿用现有错误处理，不把失败当成获得了资料；实际工具调用计入预算。

默认模式允许清楚标记的背景知识；严格模式仍只允许基于可见原文的回答，没有证据时可以返回资料不足。按需检索不扩大引用权限，模型无法引用仅存在于磁盘、但未实际发送的行。当前仍将资料收集决策与最终结构化回答分为两个模型阶段，取消自动搜索不等于将二者合并。

资料列表默认只使用当前文档，额外资料需要勾选；切换阅读文档不会自动将曾打开过的文档全加入范围。当前文档的复选框显示勾选且不可取消。取消焦点不会清除额外资料勾选。

API 保留 `focus_document_id`、`focus_source_id` 字段名以兼容现有请求，它们现在同时标识当前文档及版本。`line_start`、`line_end` 可同时省略或为 null，表示无选段；只给一个行号会拒绝。无选段时 `focus_context` 返回 null。网页显式选段使用 `document_focus()`，与 Agent 的 `read_source` 每次 200 行限制独立；练习出题仍保留已有选段流程。

## 超长内容处理

1. `chunk_source()` 保留 Markdown 结构与字符软上限，离线预览不加载模型。
2. 首次检索时 `LocalEmbedder.prepare_chunks()` 检查完整 embedding 输入，包括章节路径、角色前缀和特殊 token。超长多行片段拆成连续原文行片段，继承章节信息并生成稳定的新 ID。
3. 单行自身就超限时，保持该行原文完整。`_windows()` 将字符连续分窗口，每个窗口重复模型角色前缀，并通过同一个 tokenizer 验证；所有字符均参与编码。
4. 同一长单行的各窗口向量按原文字符长度加权平均后归一化，得到该原文片段的一个向量。长问题也用这个兜底方案。长标题与正文一起完整编码。普通合规片段的编码保持不变。
5. `_encode()` 保留最后一层长度检查，防止模型内部默认截断。缓存配置版本升级为 `local-embedding-v2-token-windows`，已有旧向量不会混入新策略。

保留整行是为了兑现当前引用契约：标注 L29 就必须实际提供那一行原文，不能拿该行的一小段冒充整行。跨窗口合并能消除超限并覆盖全部文本，但同一长行中不同主题的向量会混合，检索精度需要以后用真实资料评估；如进一步细化到行内检索，需要同时引入字符位置与更细的引用契约。

RAG 的候选相似度不代表事实正确率；top 3 不保证覆盖全部信息。检索与引用验证保证资料范围和可追溯性，答案语义仍需模型理解。

## 仅依据资料的生成约束

真实网页验证发现，原来即使标记 `source_only`，生成接口仍允许 `supplement` 类型；模型可能先生成补充内容，再被本地严格模式拒绝。现在 `answers.py` 定义 `SourceOnlyAnswer`，严格模式的生成 Schema 只提供 `grounded` / `inference`，且每个内容块至少一个引用；`model_client.py` 根据模式选择 Schema，再统一转换回 `NoteAnswer`。这些结构约束通过 API 传递，提示词不增加格式或硬性要求，本地引用验证也继续保留。

该约束能拒绝不合规结构，不自动证明陈述与原文语义一致；兼容服务若不遵循 Schema，仍由本地校验报错。

## 模块分工

| 模块 | 本次变化 |
| --- | --- |
| `web/static/app.js`、`web/templates/index.html` | 默认整篇文档、可选焦点与取消按钮、仅主动勾选额外资料 |
| `web_app.py` | 可省略的行号、完整文档允许范围，交给 Agent 决定工具调用 |
| `agent_loop.py` | `document_focus()` 与模型按需工具决策，可见原文和真实工具步骤累积 |
| `knowledge_tools.py` | 索引建立前执行 token 分块，后续查询复用准备后的片段与向量 |
| `embeddings.py` | tokenizer 预算、按行细分、完整窗口编码、缓存策略版本 |
