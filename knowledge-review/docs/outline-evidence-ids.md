# 学习清单：稳定证据 ID

## 2026-10-28 更新：覆盖正式学习目标提取

此前只覆盖概述归并，D04 的正式提取仍返回自由坐标，将 L1–9、L11–25、L27–32 合成 L1–32，越过未提供的空行。现在 legacy、V1 全文/分层正式提取及 V2 直接提取统一使用证据选择。原概述归并机制保持，下文原版范围说明属于此次扩展前的历史。

### 新契约与执行顺序

1. `outline_evidence.extraction_evidence()` 复用 Source 的 Document/ContentBlock，将结构块与本次实际可见片段求交。段落、列表、代码和表格片段可单独选择；解析结构外的非空文字也登记。没有额外读取原文或扩大可见范围，不把整批原文默认注册为一个大 ID。
2. `bind_evidence()` 将 `available_evidence` 加入真实请求，ID 沿用来源版本与精确范围的 SHA-256 规则。V2 额外提供 `primary_evidence_ids`，区分主要原文与辅助表头/定义。旧来源或其他窗口的 ID 即使合法存在，也不自动获得本次授权。
3. `OutlineDraft`、`FullOutlineDraft`、`DirectOutlineDraft` 的 proposals 改用 `EvidenceLearningProposal`。其 knowledge 只有 name、statement、content_tags、evidence_ids；模型不能再返回 source_id、line_start、line_end 或 citations。字段类型和未知字段由完整 Pydantic Schema 校验，ID 归属由后端本次白名单校验。
4. `outline_service.resolve_proposals()` 逐目标检查 ID，再恢复 `LearningProposal` 的真实 citations；同 ID 去重，离散范围保持离散。继续执行原文本、考核标准和实际可见范围校验。V2 继续要求每个目标至少一条引用完全属于主要提取范围，辅助上下文不能独立产目标。
5. 网络请求前后的预算检查使用新 Schema 与完整注册表；映射本身没有模型调用。成功批次诊断保存协议、注册表和实际选择。V2 在请求前记录注册表，失败时也保留；原始模型结果及逐次纠错继续由 structured_recovery 审计。
6. 保存数据库、审核、编辑、加入计划仍使用原 LearningProposal / Citation 坐标格式。没有数据库迁移，旧候选可读取；不会根据旧错误坐标自动猜测、裁剪或补齐证据。

移除 KnowledgeProposal 的“最多三条引用”上限：一个目标可能依赖五段或更多不连续原文，强制三条会妨碍保留必要证据。仍至少需要一个 ID，保留所有其他 Schema、来源版本及完整请求预算约束；没有改变 V1 候选数量上限、V2 软阈值或拆分条件。

### 精确校验反馈

`EvidenceReferenceError` 带结构化 validation_errors，`structured_recovery.error_details()` 原样送入原有纠错回合，最多两次重试。路径使用零起始索引，中文消息使用第一/第二个目标等自然编号。

- 未知 ID：`proposals[1].knowledge.evidence_ids[2]`、错误 ID、本次可用 ID 列表。先定位原始返回的下标，再去重，重复 ID 不会使错误位置偏移。
- 坐标可见性复查：目标、引用位置、来源、请求范围、实际可见范围和精确 `missing_ranges`。例如旧 D04 返回 L1–32 时报告缺口 L10 与 L26。
- V2 辅助证据独占：具体目标、已选 ID、主要范围及可选的 primary_evidence_ids。

Schema 仍先于证据校验。自由坐标或额外 arguments 包装会收到字段路径对应的 Schema 错误，不会通过 JSON 修复放宽契约。ID 合法只能保证坐标来自提供范围，不能保证引文在语义上支持目标。

### 兼容性和验证边界

V1 已完成步骤与旧坐标候选保留，后续提取采用新协议。V2 更新 strategy 与 Schema 摘要，旧任务拒绝混用新协议，需要新建任务；旧结果仍可查看。正式默认算法、128k/12k 配置、Gold、历史实验与调用限额不改。

`test_outline_evidence.py` 验证五段离散引用、段落粒度、窗口裁剪、ID 稳定与来源隔离、未知 ID/自由坐标拒绝、重复 ID、精确缺口、受控 HTTP 的反馈与两次重试上限。相关业务回归覆盖全文、分层、legacy、V2 表头权限、断点恢复、审核与加入。

另对真实 D04 失败返回做了离线受控回放：验证脚本明确选择本次提供的结构证据，原四个目标通过 Schema 和范围校验，第一目标保留9条更细的结构引用。记录在 `.data/outline-evidence-check-20261028/D04_REPLAY.json`，未发布正式候选。这不证明真实模型会做出同样选择或提高覆盖率；本轮没有真实模型调用，旧实验产物未改写。

## 解决的问题

章节和文档概述归并时，模型看到的是已有概述及其证据指针，而非整份原文。此前输出仍要求模型填写 `source_id / line_start / line_end`。例如输入只有 L3–9 与 L11–25，模型可能返回 L3–25，跨过未提供的 L10。`citation_is_visible()` 拒绝这样的输出是正确的；需要改进的是让模型重新生成坐标的输出契约。

2026-10-28 按用户建议，将归并阶段改为证据选择。代码入口为 `outline_context.merge_messages / execute_step / resolve_merge`。

## 实现和执行顺序

1. `available_evidence()` 将输入概述中实际已有的引用登记为字典。ID 为 `ref_` 加规范化 Citation 的 SHA-256，包含来源版本、起止行和非空 asset_id；空 asset_id 与字段缺失等价。同一引用跨排序、去重和归并层级保持 ID，相同坐标但不同来源版本不共用 ID。
2. `merge_messages()` 将概述各要点的 citations 转为 evidence_ids，并附本次请求的 `available_evidence` 映射。注册表仅包含本次输入的指针，稳定 ID 不是对其他步骤或其他资料的访问授权。
3. 模型通过 `MergeDocumentBrief / MergeBriefPoint` 返回 text 与 evidence_ids。每个要点仍为 1–2 条依据、每份概述仍最多 6 个要点；原有文本长度限制保留。Schema 禁止额外字段，不能返回自由坐标。
4. `resolve_merge()` 检查每个 ID 属于本次注册表，然后按原值恢复 Citation。重复选择同一 ID 时仅去重，不生成新范围。未知或旧版本 ID 直接报错，不猜测、不裁剪、不修复模型输出。
5. `execute_step()` 继续执行原有空白检查、`citation_is_visible()`、来源当前版本检查、依赖版本和 attempt 检查。请求预算检查、分组容量检查及诊断都使用新的实际 Schema 和消息。
6. 保存的仍是原来的 `DocumentBrief`，包含真实 citations。请求诊断另外保存 `evidence_protocol=stable-ids-v1`、注册表及模型选中的 IDs。后续补读原文、候选提取、网页展示和已有结果读取不需要迁移。

两个引用 L3–9 与 L11–25 可以支持一个合并后的要点，但持久化后仍是两个范围，绝不取它们的最小连续包络 L3–25。若一个要点需要超过两条依据，提示模型保留为多个要点；没有提高原有输出上限，也不保证模型一定保全全部条件。

## 为什么采用此方式

- 坐标转换是确定性的程序工作，ID 选择使模型无需计算起止行，同时保留来源版本约束。相比顺序编号 ref1/ref2，内容派生的 ID 不随分组顺序变化；代价是 ID 较长，不能直接声称节省 Token。
- 仅在提示词中要求“不合并行号”仍允许模型输出任意坐标；独立的 ID Schema 加本次白名单检查减少了这类错误的表达空间。
- 自动把错误连续范围拆成若干交集会猜测模型的真实依据，还可能掩盖引用了不可见条件。本实现要求模型明确选择引用，不对错误坐标事后修补。
- 不用模型输出的自由字符串作为新的引用身份，不增设全局引用数据库；现有概述结果已足以重建本次注册表。

## 范围与兼容性

本次修改限于 V1 的章节/文档概述归并。首次基于原文生成的局部概述仍使用 `DocumentBrief`，允许精确选取窗口内的行；若直接给整个窗口一个 ID，会扩大引用粒度。正式学习目标、普通回答、V2 原文提取的引用契约未在本次改造。

已完成概述仍可复用，数据库格式不变。新执行的归并采用新 Schema，失败步骤恢复时保存新协议诊断。原有来源变化、暂停、依赖内容变化和迟到结果的防护继续生效。旧实验产物和 Gold 不改写；这是新的源码版本，后续真实比较需建立新的运行版本和源码指纹，不能冒充冻结的旧 V1 算法结果。

## 验证边界

`test_outline_context.py` 覆盖非连续引用恢复、未知/旧来源 ID 拒绝、可见范围复查、跨层稳定、重复 ID、非法范围、自由坐标被 Schema 拒绝，以及持久化重开复用。原有多层归并、请求预算、断点恢复和版本校验测试继续运行。`quality_eval.py` 的受控响应同步适配新契约。

这些离线测试验证坐标映射和流程约束，不证明真实模型会选对语义证据或提高学习目标覆盖率。合法 ID 仍可能被模型用于支持不相关的结论；正文事实支撑仍需独立质量检查。本次未调用真实模型，不因这次修复修改历史实验评分。
