# Knowledge Review：第一版产品设计与后续路线

日期：2026-09-10。

状态：用户已于 2026-09-10 确认第一版范围。本文件作为当前产品范围与需求依据；功能尚待按阶段实现，具体实现方案在对应阶段细化。

## 1. 产品定位与使用场景

为自己在本地使用的技术学习 Agent。以个人资料为学习主线，结合模型知识解释原理、补充前置知识、设计问题，并根据真实作答安排后续学习和复习。

完整愿景是一个具有学习能力的阅读器和知识库：可以阅读书籍，在原文旁提问或做小测，将书籍和个人笔记放在一起制定学习计划，并持续记录学习进展。

第一版只接入 Markdown。PDF、EPUB（电子书格式）和 Obsidian 后续接入。应用和资料存储在本地；调用云端生成模型和 embedding 模型时，相关文本仍会发送给对应服务，并非完全离线运行。

## 2. 已明确的要求

- 不把“资料没有答案”当作必须结束对话的条件，允许模型基于自身知识继续解释。
- 学习应有资料范围和目标，能够追问、出题、接收真实作答、保存记录。
- 引入 embedding 和知识库检索，支持多份资料联合学习。
- 参考 DeepTutor 精通之路与知识库的设计思路，学习相应工程机制。
- 第一版以单人、本地、技术 Markdown 笔记为范围，先形成可用的学习闭环。
- 功能按小步开发，每一步说明设计原因、数据变化和验证方法。

## 3. 资料与模型知识的平衡

### 3.1 三种方案及建议

| 方案 | 收益 | 代价 | 定位 |
| --- | --- | --- | --- |
| 资料优先，允许明确标注的补充 | 同时满足阅读核对和深入理解 | 需要区分依据、推导和补充 | 默认方案 |
| 严格依据资料 | 适合总结作者观点、检查笔记覆盖情况 | 无法充分补充背景和缺失知识 | 可选模式 |
| 模型自由回答，资料仅作参考 | 实现简单、回答范围广 | 容易混淆作者观点和模型知识 | 不作为默认方案 |

推荐方案通过来源边界控制回答，而不是规定资料和模型各占多少比例。

### 3.2 回答中区分三类内容

1. 资料依据：对原文的摘录或忠实转述，绑定资料片段和准确位置。
2. 分析与推导：基于原文中的条件进行解释，标明额外假设；引用支持的是前提，不能冒充作者已经给出的结论。
3. 模型补充：前置知识、类比、额外例子或资料之外的解释，标识为模型补充，不伪造资料引用或声称已经外部核验。

按段落或回答区块记录依据，不强制每次回答都填满三个栏目。没有足够资料依据时，先说明“当前提供或检索到的资料不足”，再给允许的补充。检索未命中不能直接断言整个知识库不存在答案。

用户问“作者如何定义……”时，忠实呈现作者的表述；用户问“为什么、怎么理解、实际如何使用”时允许扩展。扩展可超出原文，但仍应围绕当前学习目标。

若笔记可能有错误或与模型知识冲突，展示原文观点与疑点，并说明适用条件和不确定性。第一版不联网核验，不把模型判断自动当作纠正后的真相，也不自动修改笔记。

### 3.3 对现有回答结构的影响

早期原型的 `answered / insufficient_evidence` 将资料充分性和回答结果放在同一个状态中，并要求资料不足时引用为空。它适用于已有单资料练习，但不足以表达“部分有依据、部分为补充”。

设计将拆开：

- 运行结果：成功、失败、取消、预算耗尽。
- 资料覆盖情况：充分、部分、不足。
- 回答区块：资料依据、推导、模型补充，各自关联适用的来源。

阶段 A 已实现 `coverage / coverage_note / blocks`，逐段区分依据并校验来源和行号；运行失败暂由异常和退出码表示，完整持久化运行状态在后续阶段实现。

## 4. 第一版完整体验

用户导入若干 Markdown 笔记，打开章节并选中一段文字，提出问题。Agent 先理解选段及上下文，必要时检索其他笔记、读取邻近段落，再给出带依据区分的解释。

用户可以围绕当前小节直接生成一道题，也可以选择多份资料并填写学习目标，例如“每次约 20 分钟，理解这些笔记中的网络 I/O 模型”。系统生成可修改的学习清单，经用户确认后开始执行。

每个学习单元包括讲解、练习、提交回答和反馈。Agent 根据实际回答选择澄清、补讲、追问或进入下一单元。题目发出后等待真实作答，不自行模拟用户回答推进进度。

系统保存题目、答题记录、薄弱点和下一步建议。关闭程序后再打开，可以继续待答题或查看今天待复习的内容。

## 5. 第一版范围与验收

| 功能 | 第一版范围 | 验收依据 |
| --- | --- | --- |
| Markdown 知识库 | 导入多份 .md、选择本次资料范围、查看原文 | 回答和题目能定位到具体文件与原文位置 |
| Markdown 阅读 | 显示标题、正文和代码块；选段提问、按当前小节出题 | AI 能获得选段及所在小节，不只获得孤立的一句话 |
| 混合依据问答 | 默认允许模型补充，也可要求仅按资料回答 | 用户能区分资料结论、推导和补充；无依据内容不会伪装为引用 |
| 语义检索 | 导入时分块并生成 embedding，查询时召回相关片段；术语匹配补充召回 | 用改写问法可以找到相关片段，能查看实际取回的原文 |
| 简版学习计划 | 基于已选资料目录、内容分析和学习目标生成可编辑的单元清单 | 每个单元有目标、关联资料和完成要求；用户可调整顺序、跳过或暂停 |

| 持续复习 | 保存作答、待答题、学习状态和下次复习日期 | 重启后可恢复；首页可见待复习列表 |
| Agent 执行记录 | 展示使用过的工具、资料、状态和错误摘要 | 能看出检索、读取和出题发生在哪一步，失败可定位 |

第一版的“提醒”是应用内待复习列表；应用关闭时不负责系统通知、邮件或其他外部提醒。后续再增加后台调度。

第一版先针对小规模个人笔记集验收；不承诺大规模知识库性能或完整书籍级规划覆盖。

## 6. Agent 与工作流如何配合

### 6.1 程序维护执行边界

程序负责资料导入、分块、索引、来源绑定、输出结构校验、保存记录和状态转换；限制模型及工具调用次数、超时和可访问资料范围。

模型负责查询改写、选择下一步工具、解释知识、提出学习计划、生成题目、评估回答和建议下一步教学动作。

首版采用一个 Agent 运行循环，讲解、规划、出题和评分是不同任务配置，共用模型客户端和工具基础。需要 Agent 决策的地方保留选择空间；状态写入仍由业务服务校验后执行。

### 6.2 问答任务

输入问题、选段、章节上下文、已选资料范围和必要的对话历史。Agent 可以检索、阅读上下文、改写查询或直接回答；每一步工具结果回到下一轮模型输入。

只有检索片段不足以解释问题时，继续读取上下文。模型补充不需要为了显得有依据而强行附上无关引用。

工具失败后，区分重试、换查询和终止。无结果是正常结果；网络超时是执行失败。达到预算上限时明确说明完成到哪一步。

### 6.3 计划任务

全库规划不能只把目标向量化后取几个相似片段：相似片段可能遗漏其他章节。

先建立所选资料的目录与覆盖清单，再按章节分析学习目标和概念；根据前置关系安排单元，并记录每个单元关联哪些资料。资料覆盖不足的前置知识标记为补充单元，由用户决定是否纳入。

计划作为可编辑建议保存，用户确认后执行；后续根据作答提出局部调整，不悄悄重写整个学习目标。

### 6.4 出题、评分与复习

- 出题前明确本次评估哪些目标，题目和评分要点同时生成并保存。
- 理解题可以要求把原文原理应用到新场景，不局限于复述。
- 默认只考已选资料、已讲解并纳入本次目标的补充知识。未讲过的拓展题必须说明性质，不能把不会拓展题直接计为原章节未掌握。
- 保存原始答案后评分；评分失败允许重试，不丢作答、不重复累计有效记录。
- 评分引用用户答案中的具体内容，并接受用户对评语的更正。
- 学习状态先使用“未评估、需复习、初步理解、达到当前练习标准”等可解释状态，不把模型自信分数当作客观掌握率。
- 复习日期先采用简单可解释的规则，根据答题结果安排；具体间隔在实现时确定，不宣称经过科学校准。

“讲透本质”的检查点：说明要解决的问题、关键机制、适用条件和反例，并通过变化场景检验理解。展示这些教学内容和可检查依据，不依赖获取模型隐藏推理过程。

## 7. 模块结构草案

| 模块 | 主要职责 | 与其他模块的关系 |
| --- | --- | --- |
| 阅读与学习界面 | 资料列表、阅读、选段、问答、练习、计划和记录 | 调用业务接口，不直接操作模型或数据库 |
| 学习业务服务 | 管理计划、学习单元、待答题、评分和复习 | 调用 Agent；验证结果后保存 |
| Agent 运行层 | 组织任务上下文、模型调用、工具执行、预算和事件 | 调用模型客户端与工具，不直接决定持久化是否合法 |
| 知识库服务 | 解析、分块、索引、检索、原文定位 | 给 Agent 提供搜索和读取能力 |
| 模型连接 | 生成模型和 embedding 模型的请求、配置、错误处理 | 两类模型可独立配置，embedding 不负责出题或制定计划 |
| 存储 | 资料版本、片段、向量、计划、作答、状态、事件 | 支持来源追溯和重启恢复 |

推荐以 Python 后端、轻量网页、SQLite 和本地向量存储起步。生成模型沿用当前已跑通配置；embedding 模型在开发检索功能时单独选择并核对额度。首版不要求额外部署向量数据库服务。

拟议首批只读工具：列出资料目录、搜索资料、读取原文片段与上下文、读取学习记录。计划和评分等结构化结果由业务服务落库。

模块按里程碑创建，不提前生成全部空目录。

## 8. 必须保留的数据关系

- 原文版本 → 章节与片段 → 向量索引。embedding 模型、维度和分块配置需要记录；改变这些配置时重新构建对应索引，不能混用不同模型的向量。
- 回答区块 → 依据类型 → 来源片段。来源位置由程序确定，不由模型编造。
- 学习计划 → 学习单元 → 目标与资料覆盖范围。
- 题目 → 评分要点、参考依据和目标；答题记录 → 题目与用户原始答案。
- 学习状态与复习安排 → 对应的真实作答记录。
- 阅读选段 → 文档版本、章节、原文位置；后续 PDF 可使用页码和区域，EPUB 可使用章节和位置标记。

Markdown 阅读页面需要保留渲染内容与原文位置的对应关系，不能仅凭选中文字猜测它来自哪个重复段落。

资料修改后，旧题目和引用必须仍指向旧版本，或明确标记已失效；不能悄悄映射到新原文。

## 9. 开发顺序

| 阶段 | 交付内容 | 本阶段解决的问题 |
| --- | --- | --- |
| 当前基础 | 单份 Markdown 问答、结构化结果和基本校验 | 已有学习用原型；不是第一版完整产品 |
| A | 回答依据区分、多文件及稳定来源标识 | 支持资料补充与多文档引用 |
| B | 分块、embedding、检索、读取上下文工具及 Agent 循环 | 让模型能按问题寻找和补充信息 |
| C | 本地网页阅读、选段问答、资料选择和来源查看 | 把命令行能力变成阅读时可用的工具 |
| D | 持久化学习单元、出题、接收作答、评分、针对性追问 | 形成能够暂停与恢复的学习过程 |

第一版完成意味着 A–E 串成完整可用流程。每一阶段都保留可运行版本、解释变更并进行有针对性的验证。

## 12. 已确认范围与下一步

用户已确认第 5 节第一版范围，包括 Markdown 选段阅读、embedding 检索、可编辑简版计划和应用内复习列表。

阶段 A 已完成多 Markdown 命令行输入、基于路径和内容的来源 ID、逐段依据区分和严格模式。14 项本地测试及四类真实模型问答通过。资料版本只在当前运行内存中保存，尚未建立历史存档。

阶段 B 已实现保留章节与原文位置的 Markdown 分块、可选本地 embedding 模型、余弦检索预览，以及 `--question --rag` 检索问答。RAG 只发送命中片段，引用必须完全位于本次可见的原文范围内；资料不足时允许默认模式下的明确模型补充，严格模式禁止补充。模型文件与文档向量均已保存在本地。分块支持 min_chars/max_chars 相邻合并并保留跨小节元数据，embedding 上限读取所选模型配置，也可主动降低；使用所选 tokenizer 拒绝超长输入。超长原子块的自动重切与检索上下文扩展尚未实现。

文档向量现已保存到本地 SQLite，按模型指纹、输入与分块配置隔离；查询只复用本次资料版本的片段向量，变化的文件重新计算。支持强制重建和跳过缓存，尚未自动清理历史缓存或保存旧版原文。

知识库服务现已提供服务商无关的 `search_notes` 与 `read_source` 工具：搜索限制候选数量，读取只能访问当前来源版本的合法行号和有限范围；工具结果同时返回模型可见数据与程序维护的可引用片段。现有搜索和固定 RAG 已复用该工具层。

问答任务现已加入有界 Agent 工具循环：`--question --agent` 让模型在最多 1–6 次工具调用内选择搜索、改写查询、按行读取或结束；工具结果与参数错误会回到下一轮模型输入。运行层只把成功工具返回的片段交给最终结构化回答和引用校验，并在终端显示步骤与停止原因。它不等于完整学习 Agent：选段阅读、出题、真实作答、持久化学习状态和复习仍待后续阶段实现。开发协作约定维护在项目 `AGENTS.md`，`agent.md` 为入口。
