# 记忆与产品管理：第二、三批实际实现

2026-10-10。本文描述代码中的行为。跨会话检索及聊天归档/删除见 conversation-memory-phase2.md。

## 知识库与资料管理

集合可以移动到其他集合，程序在同一事务中沿父链检查，禁止移动总知识库、放入自身或后代。文件和复习项仍保持各自直接归属，父集合包含后代。

删除集合采用“内容移到上一级”：直接文件、子集合、练习及计划归属原子迁移。旧清单迁移为上一级的历史记录，撤销原范围指纹、暂停尚未完成的提取；后续整合、复查、路线和加入必须通过原有范围检查，迟到结果不能发布。没有删除题目、答案、评分或 FSRS 状态。总知识库不可删除。

导入的 Markdown 可以替换正文，文件 document_id、名称、集合保持。新正文作为本地数据库管理的当前版本，source_id 仍是路径及实际正文的哈希；原始导入文件不被覆盖。document_states 保存当前正文/修订号/移出资格，document_versions 保存操作前实际版本。这样版本切换与资格变更可事务提交，避免数据库与文件重命名两次提交之间的半成功状态。读取、问答、集合练习与清单统一从目录中的当前版本构造 Source。

“移出资料库”撤销当前目录、按 ID 阅读、问答与新出题权限，保留本机原始导入文件和已有练习的版本快照。这是资料资格撤销，不是磁盘擦除；界面明确说明。示例文件只读。替换/移出携带 expected_source_id，操作还检查服务端读取时的 revision，拒绝并发覆盖。模型请求前检查版本，发布时在事务中核对修订号与移出状态。

清单列表及详情明确显示过期；整合和路线不能继续用于当前范围，需新建清单。仅移动集合但文件集合内的范围未变时，该集合自身清单仍可有效，旧/新祖先的清单按实际范围指纹检查。练习保存的旧引用继续显示旧原文；点击时若当前资料已换版/移出，展示历史摘录，不跳转到新文件同一行。旧文档练习可继续按明确的旧版本学习，真实作答及 FSRS 保持。

## 根据讨论出题

问答区“根据这段讨论考考我”进入练习页。用户选择目标、当前语言与临时题归属，生成一道题；可查看出题缘由、原话、拟加入目标及参考要点，再自行选择加入总知识库或某个集合。不自动创建 ReviewItem，不把疑惑当作作答。

两种依据明确分开：

- 默认讨论题：当前聊天背景与相关历史提供角度，参考解释由模型拟定。DiscussionQuestion/DiscussionKnowledge 的文档引用必须为空，历史不能冒充资料。技术结论与参考标准需用户核对。
- 仅按当前文档出题：讨论只提供角度。LearningQuestionDraft 沿用文档引用契约，必须引用实际发送的当前原文。仅当前文档及已扩大的资料范围可用，历史提到文件不扩大权限。无可见原文拒绝生成。

这是用户明确发起的讨论练习，所以会搜索相关历史；普通问答的按需工具流程保持，零调用不补 RAG。全部合格历史均有资格，归档仍可召回；语言用当前选项。搜索沿用关键词/E5/RRF，未校准的排序不等于真实教学相关性。

```text
保存出题请求、领取 attempt，持同聊天 OS 锁
→ build_context：完整短聊天或摘要 + 完整近期轮次 + 早期原话
→ 给实际原话补身份/字符范围，相关历史作为可选角度
→ 完整 Schema/兼容协议预算检查，裁剪可选历史与完整原文行
→ 模型提出题目、稳定目标、出题缘由与历史指针
→ 检查原话实际可见范围、文档引用、目标标准映射及当前来源版本
→ 同一事务保存题目 + 来源依赖 + 任务完成
→ 现有真实作答/评分/主动加入/FSRS；复习变式继续带来源资格
```

chat_practice_jobs 在 practice.sqlite3 保存用户请求、状态、attempt、依赖、预算与实际范围诊断及唯一 session_id。唯一 (conversation_id,request_id) 保证重复请求只创建一题；失败可在练习页重试，刷新/重启后读取任务，已完成步骤返回原题。输入变化须用新标识。与正常问答共用同聊天 OS 锁，避免同聊天并发背景错乱；其他聊天可独立处理。网络与 embedding 不持数据库写事务。

practice_basis 保存 session_id、来源聊天修订号、经过校验的原话引用及依据类型。题目/知识/目标仍使用已有学习表，DiscussionQuestion 单独扩展 Schema，原文档 Schema 的最少一条引用不放松。评分沿用语义判断、真实答案引用和标准映射，不使用关键词计分；讨论题评分也明确参考标准的模型性质，可更正。查看参考要点仍记录支持情况。追问仅用户选择后开始，不生成第二次复习事件。

## 删除与在途任务

两个既有 SQLite 文件通过 ATTACH 的短事务联动，默认磁盘数据库及 DELETE 日志模式。删除聊天时，按当前聊天依赖传播的受影响来源，撤销相关练习 basis、清理复制的原话摘录与任务诊断、撤销在途 attempt；真实题目、答案、评分及调度记录保留为只读学习记录。

生成、兼容回退、评分和变式请求之前复查；保存题目、反馈、新计划及变式时在同一事务中复查来源。因此删除期间收到旧模型结果不能发布。来源失效的题不能继续作答、查参考、评分、更正评分、生成变式/新维度或重新加入；已保存真实答案不删，已有 FSRS 日期不改。计划界面标记来源撤销。其他目标的模型参考历史排除已撤销会话，防止通过 related_history 绕过。

这与文档移出不同：文档练习明确保留旧版本作为原文依据；删除聊天必须撤销讨论及派生内容的使用资格。保留学习证据不代表允许再次送入模型。

## 请求预算与限制

复用 GenerationBudget：计算系统任务、当前目标、语言偏好、摘要/近期原话/补回、历史指针、资料、完整输出 Schema、兼容函数协议及开销，预留输出和安全余量，出题选资料另留 2048 估计空间。先减少可选跨聊天历史，再按完整原文行限制文档；实际范围随裁剪收缩。必要背景不安全容纳时保留任务并失败，原话不改。评分、变式、兼容回退独立检查实际请求。计数是 UTF-8 字节保守估计，不是当前生成服务精确 tokenizer；容量依赖现有配置，默认不能当作服务承诺。

当前每次生成一道可审核的临时题，不自动从整段聊天建立完整知识清单。尚未实现多题批量审核、题目编辑界面、历史纠正关系、全局画像、后台摘要队列、物理文件清除/恢复和版本浏览。历史全扫描、召回阈值、模型拟定标准及教学效果仍需真实评测；结构/引用合法不证明语义正确。删除撤销较保守，可能需要从当前资料创建新题。
