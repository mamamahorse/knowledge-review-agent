# 跨会话记忆与聊天管理：第一批实际实现

2026-10-10。本文件记录第一批行为。第二、三批知识库/资料管理与聊天出题已实现，见 [实际实现](library-and-chat-practice.md)；第一批验证记录保留为历史。全局用户画像仍后续。

## 用户可见行为

左侧可筛选标题、归档、查看归档列表、恢复和删除聊天。归档聊天继续有记忆资格；默认列表只显示未归档聊天。最后打开的归档聊天刷新后也能恢复。删除不可恢复，页面有明确确认；后端删除幂等，未知身份仍报错。

Agent 可以按需调用 `search_conversations(query, top_k)` 和 `read_conversation(message_id, start_offset, end_offset)`。全部可用本地聊天自动具有检索资格，不要求逐个勾选，没有年龄截止。普通对话允许零调用；没有固定历史检索或文档 RAG middleware。

回答中“关联历史”单独显示说话者和原话，点击查看并可打开原聊天。历史只能证明当时说过什么，不能证明技术结论正确；历史助手解释不会成为文档依据。严格模式仍使用原 `SourceOnlyAnswer` 内部契约，历史引用不补足文档引用、不增加资料覆盖，也不扩大本轮文档权限。

## 一条消息的数据流

```text
保存用户原话与幂等轮次
→ build_context：当前聊天原话/摘要/近期对话，捕获来源版本
→ Agent：同一背景 + 当前材料范围 + 文档/历史工具定义
→ 如需旧讨论：搜索全部合格原话，补同轮问题/回答，按完整请求预算裁剪
→ 记录真正发送的历史范围及来源版本
→ 最终回答：同一聊天背景 + 历史结果 + 真正可见的文档原文
→ 两种引用分别校验
→ 在保存事务内再次检查来源版本，保存用户可见回复和依赖
```

工具结果在 Agent 的后续工具消息中可见，最终阶段通过 `ContextBundle.memory_spans` 收到这些历史。`memory_dependencies` 同时包含当前聊天和工具使用的聊天版本，`history_visible_ranges` 记录最终实际可见范围。原话不裁剪、不改写；字符裁剪只影响本轮视图和对应引用权限。现有语言选项、资料版本/选段、结构化输出原生/函数兼容机制沿用。

## 为什么这样存储

继续使用 `conversations.sqlite3`，没有新增数据库服务或依赖。

| 数据 | 作用与取舍 |
| --- | --- |
| conversations.archived | 只控制日常列表，不控制记忆权限 |
| conversations.memory_revision | 撤销迟到的工具、回答、摘要和标题；新增消息、改标题、归档不使正常请求失效 |
| turns.memory_valid | 其他聊天中依赖已删除来源的助手回复仍保留为记录，但不再送入模型或检索 |
| memory_dependencies | 轮次与来源聊天的关系；删除时沿依赖传播，当前聊天后续回复继承此前有效回复的依赖 |
| memory_vectors | 原话片段 ID/字符范围/内容哈希/embedding 配置指纹和向量；与文档向量完全隔离 |
| conversation_tombstones | 仅保留删除身份和时间，用于幂等；不保留标题或原话 |

选择把历史向量放在同一个 SQLite，是为了使撤销、原话清理和向量清理在同一事务内完成。不是把数据库事务延长到模型或 embedding 调用期间。

## 检索实现与预算

仅实际调用历史搜索时扫描合格的已完成原话；失败/跳过轮次不被视为完成讨论。用户原话保持合格，已失效的派生助手回复排除。长消息按 800 字符视图、640 字符步长形成覆盖全消息的重叠片段，引用仍使用原始字符位置。检索大小不决定生成请求是否能放入窗口。

关键词使用英文/数字/代码词和明确的中文二元字符片段，不宣称是中文分词。语义搜索沿用本地 E5 配置，完整 tokenizer 窗口处理沿用 `LocalEmbedder`；缓存身份包含模型参数、tokenizer、前缀、运行库与窗口策略。每批最多编码 32 个缺失片段，不持 SQLite 写事务；落库前检查来源版本。首次搜索可能较慢，其他模型配置的缓存不会混用。

两路按名次 RRF 融合；相关排序优先，时间仅破同分，无年龄衰减。语义候选最低相似度 0.78 是当前应用启发式，不是经过校准的相关概率；关键词候选可独立进入。结果提供命中词、语义相似度及融合原因。不相关时可返回零条。最多 5 个命中消息，补同轮另一说话者最多 800 字符；直接读取每次最多 1400 字符，长消息尾部可按范围继续读取。没有把历史永久截掉。语义模型不可用时显式退回关键词，不丢输入，也不偷偷改用其他模型。

生成端继续使用明确标注的 UTF-8 字节保守估计，不用 E5 tokenizer 计算生成容量。Agent 每次追加结果、最终原生/兼容 Schema 都重新计入系统、当前问题、当前聊天、资料、工具和结果、偏好、协议开销及输出/安全预留。历史结果先按实际 Agent 剩余空间裁剪；最终阶段再减少可选历史，随后按原规则调整可选文档原文。所保留的当前问题、必要选段和原始档案不被静默截断；无法容纳则保留输入并失败。被裁掉的历史范围不能引用，即使它曾在 Agent 阶段出现。

## 删除与并发

删除不等待 OS 生成锁或网络返回。在短写事务内撤销身份、清理本聊天消息/轮次/摘要/全部配置的向量，并通过依赖图标记其他聊天的派生回复不可再用；撤销相关摘要，清除已保存的历史引用摘录和上下文快照，重置派生自动标题。用户手动标题和其他聊天原话仍是记录。

其他聊天的失效助手回复仍可查看，页面明确提示不再参与记忆；原始用户问题保留。传播按聊天依赖较保守，可能使一些独立解释也需要重新生成，以免间接复制的历史绕过撤销。此次没有聊天出题，所以不修改练习、真实答案、学习计划或 FSRS 记录。

请求在每个 Agent 调用及最终结构化输出的兼容重试前检查来源；保存回复时在同一事务内检查来源。摘要发布同时核对来源 revision、旧摘要版本和原话指纹，标题靠 attempt 与来源检查拒绝旧结果。已发送的远端请求不能撤回，但失效结果不能发布；当前聊天未删除时用户输入保留，可重试且仍是同一轮。

这是应用层撤销与数据库记录清理，不承诺对 SQLite 空闲页、磁盘或用户自行保留的备份做安全擦除。对话删除后的原话也不能从失效派生回复重新送给模型。

## 核心代码阅读

1. `conversation_store.py`：先看 delete、check_dependencies、finish，理解原子发布和间接撤销。
2. `conversation_memory.py`：工具参数、分片/召回/缓存、可见范围与独立引用校验。
3. `conversation_context.py`：共用背景、当前聊天摘要、来源版本快照。
4. `agent_loop.py` / `model_client.py`：工具结果进入两个阶段，完整预算与文档/历史引用分工。
5. `structured_output.py`：兼容请求间也检查撤销状态，不改变原有服务降级机制。
6. `web_app.py` / `web/static/app.js`：持久链路、管理入口、原话对话框及归档恢复。

## 验证与限制

`python -m unittest test_conversation_memory` 为受控契约、预算、迁移/恢复和竞态测试；不证明模型理解能力。`python quality_memory.py --mode smoke` 使用合成档案、受控向量和受控模型，不访问当前服务；`--mode live` 才调用当前真实模型和本地 embedding。`--output-tokens 8192` 只更改评测的输出预留，仍受完整输入预算限制，不修改应用配置。

当前真实样例使用合成旧讨论：找到归档的 1990 年 ACK 例子，回答 ACK=130，返回独立历史引用；另一条问候零工具调用、未加载 embedding。前面失败的样例包括输出截断和历史解释被误标为无文档引用的 grounded，均被拒绝并保留报告。澄清历史回答 Schema 后一次样例通过，不能据此承诺每次生成通过或普遍召回效果。

仍未实现：全局用户画像、历史纠正关系自动追踪、原话编辑、摘要更正界面/后台队列、物理文件清除与恢复、多题批量审核和版本浏览。检索目前扫描全部合格原话，首次编码成本随历史增长；阈值、候选多样性和摘要忠实度需要进一步真实评测。来源合法性校验不证明语义引用支持结论。
