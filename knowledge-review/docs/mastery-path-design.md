## 1. 这个模块实际解决什么问题

现有项目以一次选段练习为中心：生成题目、回答、逐项评分和最多三道题的追问。DeepTutor 的 Mastery Path 以长期学习目标为中心：围绕目标建立模块和知识点，持续保存评估证据，推荐当前学习目标，并安排复习。

`capabilities/mastery` 主要是 Agent 接入层。掌握度、调度、数据和事务的大部分实现位于 `deeptutor/learning`，界面与恢复还依赖 API 和会话运行时。只复制 mastery 文件夹不能得到完整功能。

### 1.1 从目标和材料建立学习路径

路径包含多个有顺序的模块，每个模块有一句能力目标和若干知识点。知识点区分记忆、概念、程序、设计四类。另有学习者背景、目标水平、时间预算和偏好信息。

主题来源模型支持文件、知识库、书籍、笔记、聊天、题库记录等。主题草稿生成会读取文件或检索知识库，并带上文档清单；界面/API 可展示草稿后确认建立主题。Agent 教学手册也引导与用户讨论大纲。

注意实现边界：来源输入有数量和文本预算；知识库使用有限检索。文档覆盖报告是根据模型报出的文件名匹配，不是逐项核验原文知识是否真正完整。大纲征求意见主要是交互流程与提示词意图，不能理解为程序证明用户已认可每个知识点。

### 1.2 规划、学习、复习三个模式

- `outline`：设计或调整模块与知识点。
- `study`：初次探测、解释、练习和评估。
- `review`：复测已掌握内容，也允许未到期时主动复习。

模式是聊天状态，可以在同一聊天切换。工具执行时检查权限，例如已记录模式的学习会话不能直接重建大纲，须先切换到规划模式。旧会话、CLI/SDK 缺少模式时有兼容放行行为，不宜把它说成所有入口都严格受限。

复习工具会拒绝尚未掌握的知识点，这是 DeepTutor 的具体产品选择。我们的复习应包含学过但答错、遗忘的目标，避免“需要重学”反而不进复习队列。

### 1.3 由学习证据决定推荐进度

`policy.next_objective()` 的默认推荐顺序：

1. 已发出但尚未处理的题目。
2. 到期复习。
3. 按模块与知识点顺序，第一个尚未过关的目标。
4. 都已过关且无到期项时，报告当前完成。

未测试的目标建议先探测；量化目标低于门槛则继续练习；概念/设计目标建议解释与评估。推荐来自当前证据，不靠固定的“第几节课”游标。Agent 仍可响应用户点名的目标；这不是严格锁死所有教学动作的状态机。

### 1.4 不同知识类型用不同过关证据

| 类型 | 判定方式 | 源码中的门槛 |
| --- | --- | --- |
| 记忆、程序 | 答题正确与否的近期加权表现 | 至少达到 0.9 |
| 概念、设计 | Agent 调用 `mastery_assess(passed, feedback)`，记录定性结论 | 一次已记录的通过即可过关 |

此外，用户可以明确声明“我已掌握”，系统允许路线继续，但区分 `learner` 自述和 `system` 评估证据，不把自述改写成系统实测。

### 1.5 题目、回答和恢复是持久状态

题目先保存，标准答案与解析在服务器保留；前端未作答前拿到的公开题目不含答案。一个学习路径只保留一个活动题目，重复出题会重新展示原题。

出题后结束当前请求，用户回答作为下一条消息处理。用户先问别的问题、刷新页面或暂时离开，不需要让后台 Agent 一直等待。待答卡片仍可恢复；跳过只放弃题目，不增加掌握证据。

选择题卡片的答案可以在模型回复前由程序立即判定，再把结果交给模型解释。作答按 `question_id` 在事务中提交；已评分重试返回已存结果，避免重复增加记录。路径版本、事件和执行期间的路径租约用于处理多个会话/入口的修改冲突。

### 1.6 长期进度和复习可见

网页有大纲、知识点状态、学习地图/看板、复习时间和会话入口。路径独立于聊天，用户可以换聊天继续同一目标，也能暂时离开目标再回来。

## 2. 它的算法到底是什么

### 2.1 掌握度是近期表现指标

`compute_mastery()` 只取最近五次的布尔正确性，按从旧到新的权重 `0.5, 0.7, 0.85, 0.95, 1.0` 计算加权平均；不足五次时使用权重的后缀。只有一次记录时结果最多 0.5，两次最多 0.8。

因此记忆/程序型连续答对一、二、三次，显示值分别为 0.5、0.8、1.0，第三次可达到 0.9 门槛。这个限制防止一次蒙对直接过关，但仍无法证明长期记忆或迁移能力：同一时段重复原题也可能累积通过，公式没有纳入题目相似度、提示使用或延迟测试。

概念/设计型的一次定性通过会显示 1.0。**界面的 100% 在这里是过关显示，不是经过校准的“永远会答对的概率”。**

### 2.2 复习采用固定间隔序列

| 类型 | 间隔序列，单位为天 |
| --- | --- |
| 记忆 | 0、1、3、7、14、30、60 |
| 概念 | 3、7、14、30 |
| 程序 | 3、7、14 |
| 设计 | 14、28 |

首次初始化使用序列第一项。答对一般向后移动一档；累计连续两次答对的那次向后移动两档；答错向前移动一档并重置连续正确次数，最后按当前时间加选定间隔生成下次日期。

已经到期的任务，先处理仍有活动错误记录的知识点，再按记忆、概念、程序、设计排序。它没有个体难度/稳定性模型，也没有基于用户历史优化参数。

**这是自定义的阶梯间隔算法，不是 FSRS，也不是标准 SM-2。** 可以参考实现分层，不能把参数和公式当成已验证的学习规律。

### 2.3 判题也有明显简化

`learning/grading.py` 的默认规则：选择题比较归一化答案；短答题允许精确匹配，较短标准答案也允许字符串相似度达到 0.85；开放题按标准答案分割出的关键词，检查用户答案覆盖是否达到 0.6。

这些规则对受控选项可以有效，对语义表达不可靠：措辞相近可能含否定错误，表达不同也可能正确。概念/设计改由 Agent 判断，但核心记录仍以通过/不通过和反馈为主。

我们的技术问答应继续使用逐项 rubric、用户原话和来源依据，不照搬字符串/关键词判题。严格可解析的选择题或计算结果以后可以增加确定性判题，作为补充。

## 3. 值得借鉴的突出设计

1. **路径比聊天活得更久。** 学习状态挂到稳定知识点，不能因换聊天或重启消失。
2. **教学与过关规则分工。** 模型决定怎么问、怎么解释；程序管理证据、候选目标、权限、时间和状态。
3. **用证据推荐下一步。** 能做探测、跳过已证实的知识、回到薄弱目标，而非永远按章节直线前进。
4. **用户能改学习方向。** 大纲、学习、复习有可见入口；主动复习不必等到期，自述掌握与实测结果有不同来源。
5. **把未完成交互当成数据。** 原题、真实回答、评分和待答状态保存，重试与恢复不会靠模型猜测。
6. **界面解释学习状态。** 用户能看到路线、证据和复习安排，也能暂时退出学习。

不建议直接搬入其插件注册体系、多个数据面、完整通用工具循环和长篇强制协议提示词。当前项目需要的是上述行为及确定性边界。

## 4. 与本项目的真实差距

| 能力 | 本项目现在 | 建议补充 |
| --- | --- | --- |
| 文档/选段出题 | 已有，复用分块和有限检索 | 建立可复用的知识目标和资料关联 |
| 评分和追问 | 已有逐项 rubric、原话摘录、引用校验；一次成功生成含反馈和追问 | 关联目标评分点与长期证据，增加评分修订 |
| 记录恢复 | 练习、答案、评分、原文版本快照已保存 | 跨多次练习的计划和知识点状态 |
| 连续聊天与跨聊天记忆 | 只有设计文档，尚未运行实现 | 按既定 ContextBundle 方案实现共享上下文 |
| 掌握状态 | 当前题目的评价，不能当长期掌握率 | 未测试、学习中、已验证、需要复习等证据状态 |
| 下一目标与复习 | 尚未实现 | 模式对应的选题策略、复习调度与待办列表 |
| 评分更正 | 当前只能保存更正备注 | 保存新采纳版本并重新计算学习状态和计划 |

已有单次练习的三题上限仍适合控制一次小测成本。长期学习通过新的练习轮次持续推进，不把路径限制成三道题，也不简单取消上限后让模型无限追问。

## 5. 本项目推荐方案

### 5.1 产品入口与用户选择

保留“临时练习”，增加“学习计划”工作区。临时练习结束或讨论到值得巩固的内容时，提供“加入学习计划”入口；**用户选择后才创建长期复习安排**。

两种加入方式：

- 单个目标：从这道题/这次聊天生成一个可编辑的知识目标，选择加入已有计划或新计划。
- 一组材料：选择文档或知识库范围和学习目标，生成模块与知识点草稿，用户可删改和开始学习。

这里的确认是用户选择学习范围和是否加入计划，不是要求逐个知识点向开发者或 AI 请求审批。临时出题照常可以直接进行。

工作区提供“学习新知识”“到期复习”“选择知识点练习”三个动作，能暂停、继续、查看依据和调整计划。复习日期产生提醒和待办，不自动打开聊天或调用模型；页面内到期提示是第一步，不要求后台通知服务。

### 5.2 区分三种事实

| 事实 | 谁负责 | 示例 |
| --- | --- | --- |
| 本题表现 | 模型对照题目 rubric，程序验证结果 | ACK 含义解释正确，但漏掉序号的单位 |
| 目标证据 | 程序聚合实际作答和修订 | 定义已验证，场景应用仍需练习 |
| 下次复习时间 | 调度器读取合格复习记录 | 明天复测某一稳定目标 |

知识领域类型（记忆/概念/程序/设计）与题型（回忆/解释/应用/比较/纠错）分别表示内容性质和考法。一个概念可以用多种题型测试，不能因为标成“概念”就一次解释后永久毕业。

第一版显示证据状态及各目标评分点的覆盖，暂不包装成精确掌握百分比。当前练习通过、提示后通过、延迟独立回忆通过、用户自述掌握分别记录。若后续需要数值模型，先用真实样例校准，再决定阈值。

### 5.3 复习时间优先借鉴 Anki 的 FSRS

建议由成熟 FSRS 实现负责稳定复习目标的时间安排。Anki 的四档表示再次学习、困难、正常、容易；忘记或核心回答失败应使用 Again，Hard 仍表示成功回忆。目标保留率控制复习负担，不等于知识理解程度。[Anki 官方说明](https://docs.ankiweb.net/deck-options.html#fsrs)

Python 后端可以通过单独适配层接入 [py-fsrs 项目](https://github.com/open-spaced-repetition/py-fsrs/blob/main/fsrs/scheduler.py)，实际开发时再固定版本与序列化契约。第一版用默认参数；不在少量历史记录上假装已经完成个人参数优化。

**FSRS 负责何时复习，选题策略负责现在问什么。** 它不能直接决定课程顺序、诊断误解或衡量设计能力。

接入的关键限制是稳定测量目标：同一知识点的一道定义题和一道复杂设计题，不应随意塞进同一条回忆记录。每个目标先建立一个明确的复习目标/评分标准；等价变式可共用记录，考察不同能力的任务使用不同复习项。临时探测、即时追问和刚看答案后的复述保留教学证据，默认不各自当成独立 FSRS 复习。

AI 评分和调度档位分开。第一版默认核心失败建议 Again，独立通过建议 Good；Hard/Easy 允许用户根据实际回忆感受选择，不靠模型猜测答题耗时推断。任何自动映射都标明来源并允许当场修改。

已有练习在加入计划时可以提供学习证据，但不能伪造旧的定期复习次数。只导入能对应同一稳定目标、有真实时间和有效评估的记录；不符合调度要求的旧记录仅用于解释与选题，新复习项从真实加入/首次合格测评建立。

### 5.4 下一知识点由程序选择

程序根据用户当前选择产生推荐，用户随时可以忽略、点名目标、换题、看解析或结束；不按掌握状态锁关，也不强制补齐前置知识。候选仅来自用户已加入的计划与本次选择范围。先落实可解释的顺序，避免未经验证的乘法优先级公式：

- 有待答题时先提供恢复；允许用户先问问题，不自动按错误计分。
- “到期复习”：选择到期的已学复习项，包含此前答错、需要重学的项；也允许主动提前复习。
- “学习新知识”：可建议补当前目标缺口，再按模块顺序和已有前置目标推荐未测试目标。
- 用户点名某知识点时尊重指定目标；前置缺口只在有帮助时提示，不反复劝阻。
- 本次时长、新目标数量和复习配比由用户选择；后台单次请求仍保留技术预算，防止无限生成。

每次返回 `concept_id`、选择原因和本次考察能力。模型根据这些上下文选择问法、难度和解释。模式与目标范围用代码校验；第一版无需开放可以任意改计划的工具给 Agent。

### 5.5 小规模数据模型

继续使用 Python、FastAPI、现有网页、SQLite 和现有模型兼容接口。下面是责任划分，具体表数在实现时合并，避免为名字建立空框架。

| 对象 | 关键内容 | 为什么需要 |
| --- | --- | --- |
| LearningPlan / Module | 名称、目标、来源范围、模块顺序、当前状态 | 计划独立于一次聊天和练习 |
| Concept | 稳定 ID、可测试陈述、领域类型、目标评分点、资料版本/原文范围、可选前置目标 | 学习单位与检索 chunk 分开 |
| Enrollment / LearnerState | 加入时间、暂停状态、证据状态、各目标点覆盖、最近练习 | 未加入的临时内容不自动产生计划 |
| Attempt | 关联原题/真实回答、concept、考察能力、提示情况、采纳评估版本 | 沿用已有记录，不重复存成另一份“答题事实” |
| EvaluationRevision | 原始评分、用户更正、当前采纳版本和理由 | 可以回看并修复错误评分 |
| ReviewItem / ReviewLog | 稳定复习目标、调度状态、复习时间、档位及来源、算法版本 | 记忆调度与内容理解证据分别维护 |

Concept 使用独立稳定 ID；现有 source_id 是资料版本快照身份，不能用作长期概念身份。题目 rubric 每项关联到目标点，避免换题后只按字符串比较评分点。材料改版保留旧题依据，不能把新版本自动视为同一证据；语义目标发生变化时新建/修订目标，不能继承旧掌握结论。

### 5.6 一次回答的处理链

```text
保存用户原始回答
  → 组装原题、目标点、资料依据、历史表现和语言偏好
  → 一次成功模型生成：逐项评分＋反馈＋可选解释/追问
  → 校验真实摘录、引用范围、评分点覆盖和目标关联
  → 事务保存采纳评估＋学习证据＋合格复习记录＋下次日期
  → 展示评分依据、学习状态变化、建议复习时间和修改入口
```

不单独再调用一次模型评分。选择题以后可先确定性判定，再在同一回复请求生成解释。当前反馈生成阶段可以产生当前目标的追问；换到新知识点应由程序先决定目标再生成，不能直接采纳模型随意选择的新目标。

并发请求不在模型生成期间长时间占用数据库事务。提交前核对题目和状态版本，以 `attempt_id + evaluation_revision` 防止重复更新；生成失败保留真实回答并可重试。刷新、重复点击和网络重试都不能增加掌握证据或推迟两次复习日期。

评分更正保存新版本，随后按时间重放该目标受影响的证据和复习记录，使用记录的算法版本/参数快照；不按“现在”简单加减一次分数。若更正改变待答题的推荐目标，保留已经发出的题，展示计划变化，不偷偷替换用户正在回答的问题。

### 5.7 与聊天记忆方案衔接

按 [会话记忆方案](<E:/agentic project/knowledge-review/docs/conversation-memory-design.md>) 实现统一 ContextBundle：当前聊天整体表示、相关早期原话、相关其他本地聊天、指定材料/知识库检索，再加入当前目标和学习证据。

聊天有助于识别疑问、比较解释和推荐探测目标；没有实际测验证据的聊天不能直接提升掌握结论。聊天历史也不能扩大用户选定的材料权限。

归档聊天照常可召回；删除撤销原话及派生记忆的使用资格。学习计划如果引用聊天，也要登记来源依赖，删除后停用聊天原文及其派生依据并重新核对证据；可以继续使用仍存在的文档依据解释同一知识。删除后的不可用内容不能从题目快照、学习反馈或摘要绕路重新传给模型。

## 6. 建议开发顺序：交付完整闭环

### 第一批：文档/现有练习进入长期学习

交付加入/暂停计划、稳定知识目标、目标点与题目关联、学习状态和评分依据页面、真实评分更正，以及基本待复习列表和 FSRS 适配。这一批应能演示：临时练习 → 用户加入 → 作答 → 展示状态和日期 → 更正 → 刷新/重启后继续 → 到期复测。

先从已存在的文档与选段入口实现；批量材料生成大纲作为后续能力，不能把只创建表和界面壳当成本批交付。

### 第二批：知识库学习路径与自适应问法

交付资料范围/文档清单、分批读取与提取目标、来源关联、合并草稿与缺漏提示、模块大纲、新目标选择、前置缺口提示、回忆/解释/应用/纠错变式与主动复习。不要仅对整个知识库检索 top-k 后声称完成所有内容的目标提取。

知识库第一版可以是现有文档 ID 的命名集合，底层复用已有检索索引，之后再扩充导入格式，不必先更换向量数据库。

### 第三批：连续聊天与学习路径共享上下文

按既定记忆方案完成持久聊天、长会话摘要/原话检索、跨聊天召回、归档/删除失效，再接入“根据这段聊天考我”。与学习目标关联但不强制加入计划。若用户把聊天出题列为当前优先事项，可将这一批提前；前两批的资料型闭环不依赖先完成全部记忆系统。

## 7. 验收与待讨论取舍

关键验收包括：未加入不产生复习安排；重试不重复累计；更正能改变证据及日期；跳过不按答对/答错记入；提示后作答区别于独立回忆；提前复习与复习失败都能记录；重启恢复待答题；原文改版不污染旧题依据；删除聊天后不能经学习记录回流；同一目标变式与不同能力测量分开。

真实样例至少覆盖：同义正确答案、带否定的错误答案、部分正确、提示后正确、延迟后答错和用户更正。程序测试验证事务和状态约束，真实模型样例检查评分解释；二者都不能替代长期教学效果评估。

已确认的产品决定：

1. 先做现有练习加入计划并可复习；知识和问题的数据结构先讨论，再进入运行代码实现。
2. 学习路线仅作建议，不强制锁关、不替用户决定学习顺序。
3. 首版复习档位默认建议并允许当场修改。
4. 到期默认生成同目标变式，保留重做原题入口；调度应绑定稳定的考察目标。

待讨论的是知识单元粒度、可复用考察目标的定义、变式可比范围、评分证据与目标的映射，以及调度记录如何修订。FSRS 仍是建议接入的时间算法，具体接入参数和规则尚未定稿。
