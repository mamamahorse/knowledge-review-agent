# 学习闭环第一版：实现与代码阅读

日期：2026-10-03。本文描述运行代码，设计演进见 [知识与题目模型](knowledge-question-model-design.md)。

## 1. 已实现的操作

1. 从选段生成练习，题目附带知识内容、能力目标、范围与参考标准。
2. 点击“加入学习计划”才建立复习项；可以作为新知识点，也可以手动归到已有知识点。
3. 学习计划按知识点展示，回忆、解释、应用、辨析目标分别保存复习日期。
4. 默认选择同目标变式，也可以重做原题；已有待答题先恢复，不覆盖它。
5. 提交真实回答后，模型一次成功生成整体判断、参考点覆盖、原话依据、能力观察、反馈、建议档位和可选追问。
6. 默认采用模型建议的 Again / Hard / Good / Easy。用户可以修改档位，也可以修改整体判断、评分点、评语、题目范围判断及建议档位。
7. 评分修订保留原始答案和每版评价，复习日期按原始事件时间重新计算。
8. 可以暂停、恢复、提前复习、查看参考或结束。追问需要点击“继续一题”，不强制进入下一题。
9. 刷新或服务重启后，计划、日期、答案、评分修订、待评分状态、追问候选都可恢复。

本版是本地单用户模型；问答聊天历史、跨聊天记忆、自动提取整库目标、覆盖式学习路线及主动通知仍未实现。

## 2. 为什么把实体分开

```text
原文快照 → KnowledgeUnit（知识内容）
               ↓
          LearningTarget（能力、范围、稳定标准）
               ↓                 ↘ 用户选择加入 → ReviewItem（FSRS 状态）
          Question（原题/变式）                        ↑
               ↓                                     │
          Attempt（真实作答）→ EvaluationRevision → ReviewEvent
                                   ↓
                          按目标聚合的学习证据
```

“ACK 是下一个期望字节序号”是知识内容；“在连续、无缺口数据中计算 ACK”是目标；某题的 SEQ/LEN 数值是题目条件。换数值会生成新题目，仍使用同一个目标的复习状态。

目标标准在当前目标内使用从 1 开始的稳定序号。首版目标内容不原地修改，因此映射由目标身份与标准序号共同确定；以后修订范围或重排标准需要新目标版本，不能覆盖旧映射。

一张原题可以有多次 Attempt，每次回答各自保存。更正评分创建 EvaluationRevision，不能当成用户又做了一遍题。只有主要目标的有效作答会更新一个复习项，关联能力观察只作为证据供后续模型参考。

没有为每个维度预填 mastery 小数。页面展示实际作答、评价来源和提示情况；未测试显示无证据，复习到期也不把能力归零。

## 3. 实际 SQLite 表

继续使用 `.data/practice.sqlite3`，没有新增数据库服务。

| 表 | 保存什么 | 分开的原因 |
| --- | --- | --- |
| `knowledge_units` | 内容身份、名称、陈述、标签及引用 | 同一内容下可以有多个能力目标 |
| `learning_targets` | 知识点归组、能力/范围/稳定标准、原题、资料会话、原题评分点映射 | 变式按同一合同生成；各目标保留自己的来源，即使手动归到同组 |
| `learning_questions` | 不可覆盖的题目内容与来源会话 | 重做原题复用题目身份，变式另存新题 |
| `practice_sessions` | 练习状态、原文版本、可见范围、语言、复习项及模式 | 使用旧状态机保存中断的任务 |
| `practice_questions` | Attempt：题目引用、目标、回答、提示情况、当前评价版本；兼容保留旧题目 JSON | 保留旧 ID 和已有 API，迁移不破坏旧练习 |
| `evaluation_revisions` | 每版完整评分、模型/用户/历史来源、理由、时间 | 可查看原评分与更正，不覆盖历史证据 |
| `review_items` | 目标、启用/暂停、初始/当前 FSRS Card、参数、算法版本、下次日期 | 时间状态属于目标；采用的算法和参数可以回放 |
| `review_events` | 作答、评价版本、原始复习时间、建议/生效档位、选择来源、是否计入及原因 | 一次作答唯一对应一个事件；更正不新增复习次数 |

旧数据库自动增加列和表，为原题创建题库引用，为旧评分创建 `legacy` 修订。不会把旧 missing 解释成明确误解，也不会生成旧题的复习日期。旧题首次加入计划时，才结合原题和资料提取可复用目标；这个独立模型任务不重新评分。

## 4. 建议的代码阅读顺序

| 文件/入口 | 为什么这样做，改变了什么 |
| --- | --- |
| `learning_types.py` | 定义 KnowledgeDraft、TargetDraft、能力及档位。范围和稳定标准与题干分开，避免每个数值题都变成新知识点 |
| `practice_model.py` → `generate_question()` | 一次出题同时生成知识/目标和本题参考答案；`criterion_indices` 把本题评分点映射到目标标准 |
| `learning_service.py` → `enroll_question()` | 新题直接使用已保存的目标，旧题才进行语义整理。重试先检查已加入状态，不重复调用模型 |
| `learning_service.py` → `start_review()` | 先恢复待答任务，再选择原题或生成变式。模型输入固定目标、原题、近期表现及同知识点其他能力证据 |
| `practice_store.py` → `submit_answer()` | 原始回答和提示情况先在事务中落库，再做模型请求。请求失败仍有答案可恢复 |
| `practice_model.py` → `grade_answer()` | 整体判断和档位由模型给出，参考评分点不再按数量决定等级。语义理解、反馈与追问共享一次成功生成 |
| `learning_state.py` → `record_evaluation()` | 在同一事务中写评分修订、唯一复习事件和日期；重试、追问、更正不能重复计次 |
| `review_scheduler.py` → `replay()` | 只调用 FSRS 计算时间；从初始 Card 用原时间、参数和生效档位重放，保障更正后可重建 |
| `learning_store.py` → `revise_grade()` / `set_rating()` | 内容更正与档位选择分别处理。原答案不变，用户已选档位不会被之后的内容更正悄悄覆盖 |
| `web/static/learning.js` | 展示归组计划、证据、加入/暂停、原题/变式、评分修改和记录。模型文本使用文本节点呈现 |

服务层组装上下文，模型层理解语义，存储层管理事务，调度适配器计算时间。这使后续更换模型或调度参数不需要重新定义作答事实。

## 5. 模型判断与代码检查的边界

模型判断允许同义表达、合理替代解法、局部失误与不确定结果；rubric 提供参考，不能把缺一条标准机械地变成“不及格”。评分参考仍保留粗粒度的 covered/missing，整体判断另存，二者不通过计数公式互相转换。

程序检查引用是否在实际可见资料里、原话是否为用户答案真实子串、评分点是否完整分类、目标标准映射是否覆盖、作答状态及修改版本是否合法。它没有通过这些检查证明模型理解正确。

`SemanticGradeDraft` 的追问只采用 `ExerciseDraft`：题干、目标、参考评分点和引用。追问不要求生成新的知识点或长期目标，落库时作为可选教学候选；只有用户点击继续才生成待答 Attempt。

提示词表达任务意图。字段、枚举、数量通过模型接口 Schema；来源权限、映射和状态由程序校验。回答语言仍通过独立偏好上下文，任务提示词不指定中文或英语。

## 6. 日期计算与可比较性

采用固定依赖 `fsrs==6.3.2`，使用库的默认参数、目标保持率和学习步长，关闭随机扰动 `enable_fuzzing=False`。参数与初始 Card 保存在每个 ReviewItem 中，算法版本为 `fsrs-6.3.2`。

模型建议 Again 表示回忆未成功；Hard 表示成功但吃力；Good / Easy 表示成功。它可以不建议档位。程序不会根据 covered 的条数映射档位，也不推断用户真实用时；档位始终允许用户调整。

只有已加入计划的主要题目作答，整体判断可评估、题目处于目标范围内且未记录提示/参考使用时，才进入 FSRS。建议为空的事件保留记录但不推进日期。评分不确定、题目超范围、有提示后的回答与教学追问仍保留学习证据。

新加入且已经答过的题目先处于待复习状态，旧答案只作为证据，不伪造已经进行过一次计划内复习。若在原题未作答时加入，之后的第一次真实作答可以计入。

同目标变式共用 Card 是本项目的适配假设。模型和 Schema 不能证明两道题完全等价，FSRS 也不等于“应用能力的真实概率”。当前保留目标范围、原题/变式模式、提示情况和评价版本，方便之后检验。

材料本身可在阅读器及引用摘录中查看。`none_recorded` 表示没有记录提示，不能保证用户独立闭卷作答；查看参考要点自动记录，查看其他资料可自报。本版还没有完整提示事件时间线。

## 7. 修订为何要回放

假设第二次复习根据第一次的 Card 算出日期。现在把第一次的 Again 改成 Good，只修改第一次的日期会让第二次仍建立在旧状态上。

因此，更正更新同一个 ReviewEvent 的生效评价/档位，再从初始 Card 按原始作答时间重放全部有效事件。关闭 fuzz 确保相同输入得出相同日期。更正时使用 `expected_revision` 拒绝过期评分编辑，不更改已经发出的待答题。

更改评分内容后，若用户此前主动选过档位，保留用户档位；若此前采用模型建议，更新为更正后的建议。如果更正后不再具备有效复习条件，这个事件退出调度，随后日期重新计算。

## 8. 第一版明确保留的后续工作

- 知识点和目标的合并、拆分、范围修订及迁移。目前支持手动归组，目标不直接原地覆盖。
- 评分质量评估集及变式可比性检验；更细的逐标准诊断、误解候选和不确定性字段。
- FSRS 参数个性化训练、保持率选择和目标粒度校准。
- 根据整库自动提取目标、选择未学目标、学习路线建议。
- 持久聊天与跨会话记忆。当前只使用已保存的目标作答历史作为学习上下文。
- 完整提示事件记录、主动通知、多用户与同步。

本版完成现有练习的计划与复习闭环，不把这些后续能力称作已经完成。
