2026-10-04。本文件记录实际实现；后续规划不代表已完成。

## 使用流程

左侧“总知识库”是总览。其下可创建多个知识库，再在知识库内创建子集合。例如：

```text
总知识库
├─ 计算机网络
│  ├─ TCP
│  └─ HTTP
└─ 操作系统
```

创建时选择父集合；放在总知识库下就是一个新的知识库。选中集合后，用 ＋ 导入 UTF-8 Markdown 文件。查看父集合时包含子集合文件。已有导入文件和示例文件默认归总知识库；“移动当前文件到集合”可调整归属。移动只更新关联，不改变磁盘文件、文档 ID 或资料版本。

练习默认针对当前整篇文档，选段可选，不再要求选择 1–200 行。选段需在当前原文范围内并通过版本校验；过大的必要选段会明确报预算错误，不静默裁剪。练习范围也可改为集合及子集合。“学习计划”中的“从这个集合的资料开始练习”直接进入该入口。

题目生成后，可选择加入总知识库或任意集合，同时保留原有“新知识点 / 已有知识点”归组。临时题目不自动进入计划。学习计划按集合及后代筛选，内部仍按知识点归组、按能力目标分别复习。已加入的复习项可调整集合归属，日期、状态、作答和评分历史保留。

新聊天在首次成功回复保存后自动生成标题，使用当前回答语言。独立后台任务不阻塞回复持久化；失败保留聊天，下次成功对话可再次尝试。手动命名仍可用，已有明确标题不自动覆盖。

## 数据结构与取舍

集合在原有 `.data/practice.sqlite3` 中，聊天仍在 `.data/conversations.sqlite3` 中；文件仍使用 `.data/notes/` 的现有导入方式。没有新增服务或向量数据库。

| 数据 | 作用与原因 |
| --- | --- |
| `collections(id, parent_id, name)` | 父 ID 表示树；顶层和子集合使用同一对象，SQLite 递归查询后代；根 ID 固定为 `root`。 |
| `document_collections(document_id, collection_id)` | 文件当前归一个集合；永久文档身份独立于资料内容版本，不能用 `source_id` 管理文件夹归属。旧文件默认在根。 |
| `practice_sessions.collection_id` | 发起练习的资料集合，用于加入计划时的默认选择。 |
| `review_items.collection_id` | 用户选择的计划归属，独立于文件归属；移动文件不会自动挪动复习项。 |
| 聊天 `title_state / title_attempt / title_started_at` | 区分待命名、生成中、失败、已生成和手动标题；阻止迟到任务覆盖较新的标题。 |

旧练习与复习项增加默认根归属，保留原行、ID、评价版本和 FSRS 状态。SQLite 不允许给已有数据的表直接添加带非空默认值的外键列，因此这两列使用插入/更新触发器校验集合存在；集合父关系和文件关联使用外键。没有删除入口。

资料范围、题目所属知识点、能力目标和集合归属分别回答：资料从哪里来、考什么、如何调度、用户想放在哪。集合筛选不会复制复习事件。同一知识点可以通过人工归组拥有来自多个集合的目标。

## 原文与预算

无选段练习按 Markdown 结构分块，多个文件交替取块、章节分散排序；填写目标时优先含目标字面词的片段。此步骤不加载 embedding，也不声称是语义检索。显式选段保留原文及邻近行；选择额外文档时沿用原来的补充检索路径。

程序计算系统任务、资料目录、语言、目标、原文及两种结构化输出契约。整篇/集合模式为后续评分额外预留输入空间；必要选段不裁剪，可选资料按完整原文行缩小。实际请求由 `structured_output.py` 再检查预算；预留不能保证任意长度答案或累积复习历史都能容纳，失败仍保留真实作答。

题目和知识说明只可引用实际发送的原文；保存完整版本快照及实际可见行号，评分、变式和引用跳转继续使用这些快照。长资料可能只提供部分片段，一道题不表示已覆盖整篇/整个集合。没有用摘要冒充原文。

问答的 `search_notes` 仍由 Agent 按需调用；问答默认文档范围不自动扩大到当前集合或所有知识库。历史提及文件也不扩权。

## 标题任务的发布

成功保存回复后领取标题任务，以开头用户/助手回复的明确标注摘录命名，原消息不变；通过 `ChatTitle` Schema 请求当前模型，遵守完整协议预算。输出预留 512，单次超时 20 秒，关闭额外网络重试。

模型调用不持有 SQLite 写锁。发布比较 attempt；手动重命名清除 attempt，迟到结果不会覆盖它。重复任务不重复命名，中断任务可在三分钟租约过期后恢复。失败不改变轮次状态、不产生学习证据。标题只自动命名一次。

## 关键代码与接口

| 文件 | 修改后的职责 |
| --- | --- |
| `library_store.py` | 集合迁移、创建/重命名、后代查询、文件和复习项归属 |
| `practice_service.py`、`practice_model.py` | 选段可选、整篇/集合片段选择、生成预算和引用验证 |
| `practice_store.py`、`learning_store.py`、`learning_service.py` | 事务保存练习归属、主动加入、集合筛选及复习继承 |
| `conversation_title.py`、`conversation_store.py` | 自动命名、任务领取、失败恢复、手动标题优先 |
| `web_app.py` | 集合接口、整篇/集合出题、后台标题、旧接口兼容 |
| `web/static/library.js`、`learning.js`、`app.js` | 集合树、文件移动、练习范围、计划选择和标题刷新 |

新增 `GET/POST /api/collections`、`PATCH /api/collections/{id}`、文件/复习项的 `.../{id}/collection`，及 `POST /api/collections/{id}/practice`。文件列表、导入和学习计划支持 `collection_id`；原练习接口行号可同时省略。仍只接受目录中的文档 ID，浏览器不能提交任意路径。

## 运行与验证

在项目目录运行：

```powershell
.\.venv\Scripts\python.exe web_app.py
.\.venv\Scripts\python.exe -m unittest discover -v
.\.venv\Scripts\python.exe -m pip check
```

地址仍为 `http://127.0.0.1:8765/`。更新后重启服务并刷新页面；所有静态资源使用版本参数避免旧缓存。

## 当前限制与后续

仅支持 Markdown；一个文件和一个复习项各有一个直接所属集合，父集合通过后代总览包含它们。尚未提供多重归属、集合重排/迁移、删除、全库覆盖评估或自动整库学习路线。

随后已实现“从所选集合生成可审核的知识点与目标清单”，记录章节分析范围和目标加入情况，审核勾选后生成首题并加入计划。见 [集合学习清单实现](collection-learning-outline.md)。章节分析完成不代表概念完全提取或用户掌握。覆盖式学习路线、跨会话召回、历史引用、归档/删除失效链路与聊天反馈出题仍为后续交付。

用户确认的完整路线是 [大文件分层整理](collection-learning-outline.md#大文件分层整理后续设计)：共享文档概览、结构切分、跨章节整合及原文复查，再由用户审核目标和学习顺序。完整输入与输出预算共同决定全文或分层方式；默认沿用现有技术栈，框架和多 Agent 按评测需要引入。不改变当前集合归属、聊天资料权限或主动加入规则；分阶段完成状态见下面进展。
