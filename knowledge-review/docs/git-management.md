# Git提交与本机数据边界

2026-10-15：用户授权整理当前已实现功能并推送到既有远程分支。仓库原本已有Git历史，本次作为一个完整开发检查点提交，不倒造此前多轮开发的提交历史。后续功能建议分别提交，便于比较、回退和面试时追踪设计演进；本次授权不代表以后自动提交或推送。

## 哪些文件纳入版本管理

| 内容 | 原因 |
| --- | --- |

| unittest测试和质量评测脚本 | 保存行为约束，并区分受控工程测试与真实模型实验 |

| expanded-v1/results-20261013.md | 已核对的公开合成实验报告副本，保留负面结果、标签来源、分母与耗时口径 |

初审JSON虽有数MB，仍保留：它们是绑定实际片段和资料指纹的评测输入，测试和审查需要，不能因为“由程序生成”就与运行缓存一起排除。原初审与修正版本也不能只保留最新一份。模型权重不属于这类输入。

## 哪些文件不上传

| 路径或类型 | 原因 |
| --- | --- |
| .env及.env.*（保留.env.example） | 账号密钥和个人服务配置，克隆后由使用者本地填写 |
| .data/，以及任意位置的SQLite/DB及日志旁文件 | 包含导入笔记、完整聊天、摘要、真实作答、学习计划、审核数据库和缓存；原始评测Trace也与这些本机产物一起留本地 |
| .models/ | 下载的模型权重体积大，有独立版本与下载方式，不应放进Git对象历史 |
| .venv/、__pycache__/和.pyc等 | 依赖环境与解释器产物依赖本机，可从依赖清单重建 |
| .test-*/、测试/覆盖率缓存、日志、输出和PID文件 | 验收临时产物，可能含运行路径、错误或个人内容；不作为源码 |
| .idea/、.vscode/和系统目录元数据 | 本机编辑器及操作系统偏好，不是应用运行要求 |
| .pem/.key/.p12/.pfx | 私钥或证书凭据应在本地或安全配置系统维护 |
| 仓库根的三个未跟踪设计文档 | 沿用用户此前保留约定，本次应用检查点不主动纳入；原文件不删除，也不通过新增忽略规则隐藏 |

.gitignore只约束尚未跟踪的文件；若敏感内容曾提交，追加忽略规则不会从历史删除，须另行处理。本批检查当前跟踪清单及候选文件，不把“没有命中扫描规则”当作完整安全审计承诺。不会使用git add .或强制添加被忽略文件。

.gitattributes保留两套检索语料末尾空行的检查例外，冻结原文不改写。2026-10-24补充应用运行文本及适配目标的LF规则，保证干净检出与Gateway安装资产的字节SHA一致；Gateway自身安装资产使用-text保存精确字节。源码普通行尾空格仍检查，不整体关闭Git空白检查。

## 克隆后恢复什么

代码、文档和公开评测输入可恢复；个人聊天、笔记、学习进度、本机审核/冻结历史和下载模型不会随Git恢复。需要保留这些内容时，应另外做受控本机备份；运行期间的多个数据库应使用一致性备份方式，不能把Git当作个人数据库备份。

使用README安装依赖，按.env.example建立本机.env，再启动应用。embedding和Rerank模型按现有显式下载命令准备，普通检索不隐式下载。评测脚本可重建本机评测数据，但不能仅凭报告中的freeze ID恢复原数据库版本或原审核历史。
