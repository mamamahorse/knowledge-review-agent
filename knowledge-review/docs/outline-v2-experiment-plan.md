# 清单 V1/V2 与 32k/128k 小型对照实验：待用户确认

日期：2026-10-26。状态：方案，尚未运行真实模型。

## 1. 要回答的问题

1. 扩大预算是否已经足以减少V1的分层工作，还是仍受目标数和80行等规则限制？
2. 相同预算下，V2直接提取的关键目标覆盖、证据质量与重复情况如何？
3. V2的真实模型消耗和总耗时是否更合适，输出压力拆批是否抵消了省去概述树的收益？

不把“成功保存结果”当作质量通过，也不预先决定切换默认。

## 2. 最小实验矩阵

| 组别 | 算法 | 应用总预算 | 作用 |
| --- | --- | --- | --- |
| A | V1原算法 | 32768 | 现状基线 |
| B | V1原算法 | 131072 | 分离扩大预算本身的影响 |
| C | V2直接提取 | 32768 | 同预算比较两种完整实现 |
| D | V2直接提取 | 131072 | 用户希望尝试的配置 |

四份公开合成学习资料，每份四组，共16个清单任务；第一份的四组作为冒烟，成功且未触及额度后再继续其余12组。初轮不做重复采样或统计显著性宣称，也不运行归组/加入计划/首题生成。若后续讨论整个产品总成本，再另批测归组，避免本轮范围扩张。

推荐资料：

- 短而密集：多个独立定义、条件与例子，观察4/6/8项输出契约的覆盖压力。
- 长而稀疏：少量关键目标夹杂长解释及重复例子，观察分块冗余、摘要前置开销。
- 跨章节依赖：后章应用前章定义，检查条件是否被遗漏，是否存在只凭局部窗口的错误目标。
- 表格与代码：真实表头/单位/脚注、代码约束及例外，检查跨范围引用与部分表格误判。

至少两份在当前完整请求估算下超过32k输入额度且可在128k额度内直接处理。定位以完整协议估算为准，不能把文本字节数当真实token。另有超长单行、图片占位等离线边界测试，无需专门消费真实模型额度。

资料和参考目标在首次模型调用前冻结；不使用私人书籍、聊天或网页业务库。参考目标明确范围、必要条件、证据位置和关键/普通标记。可以由Agent初标，但报告必须注明非全人工gold，不能把后续模型输出反向加入测试参考来追分。资料准备后保存SHA与版本，并列出原文供审核。

## 3. 保持一致与解释限制

固定同一实际端点/模型标识、思考模式、提取方向、语言、输出预留4096、安全余量2048和现有计数方式；不在本轮同时更换tokenizer。服务存在自动升级别名时，记录返回模型及时间，报告该限制。

V1通过隔离进程环境设置32k/128k；V2显式传入逐任务预算。不要修改个人.env或默认服务。四组任务使用独立隔离库，不在同一集合同时启动，不重启现有应用。

V1/V2的提示、概述树和每批候选Schema上限存在差异，因此C对A、D对B衡量的是两种完整方案，不是仅删除摘要树的严格单变量实验。若需要归因到某个组成部分，再设计额外消融，本轮不先增加组数。

输出要求和参考提取粒度保持一致；不按最终候选条数判断谁更好。固定现有请求超时，不把超时失败静默换配置重试。组别顺序轮换并保留cache usage，避免把热缓存节省误归因于算法。

## 4. 执行控制与遥测

建议串行执行，一次最多一个真实模型请求；每个任务最多16次显式模型调用机会，全实验最多128次。包括协议回退、失败、输出截断和拆批重做；达到任一上限立即停止并保留partial/failed，不自动购买或扩额。网络失败不做自动业务重试，首次冒烟的认证/协议/服务容量问题停止后报告。

实验适配需为V1同样注入before_request/telemetry并关闭SDK隐式重试，记录每次实际返回usage；使用同一采集方式。V2已具备预算传递与观测钩子，V1使用实验适配，不改旧算法语义。当前还没有执行这套真实实验适配/任务。

16次/任务、128次/总实验为拟议的调用上限，不是预估会实际花费这些次数。先生成规划诊断和预计调用范围；真实费用使用运行当时服务单价及cache/思考等实际usage字段计算，无法取得的消耗标未知。不得用“预算估计”冒充实际账单。若需要金额硬上限，应在执行前一并确定。

所有原始结果、失败和重试留在 `.data/evaluations/outline-v2-<run-id>/` 下；公开报告只写合成资料、算法/预算身份和汇总，不导出凭据。

V2消耗汇总按每个批次的attempts遍历一次，包括superseded父批；顶层最近诊断是展示副本，不与attempts再次相加，防止重复计算。

## 5. 输出报告

每份资料、每个组分别报告：

| 项目 | 计算/审核方式 |
| --- | --- |
| 关键目标覆盖 | 是否保留关键目标的条件、范围与必要关系；缺失逐条列原文 |
| 全部参考目标覆盖 | 固定参考中正确覆盖的比例，标注标签来源与语义判定者 |
| 证据有效性 | 程序引用范围正确，以及语义上是否真正支撑目标，分列 |
| 错误与冗余 | 不受支持的目标、遗漏条件、重复目标；不同能力维度不直接算重复 |
| 处理覆盖与风险 | 未处理主范围、失败批次、饱和/拆分次数、未解决上下文 |
| 消耗 | 显式调用、输入/输出/cache等真实usage、未知usage、价格来源及费用 |
| 等待 | 首个正式候选、全部提取完成时间，失败与截断不排除 |

同时给出A→B、C→D的预算影响，A→C、B→D的方案影响。单文档单次结果不称稳定P50/P95、真实用户效果或全书分析质量。

## 6. 默认路径决策

本轮先要求：关键参考目标无新增遗漏、无新增高严重度语义证据错误、无越权引用及恢复错误；在满足这些条件的组别中比较费用、完成时间和重复情况。普通目标的差异和可接受容忍范围由报告逐项呈现，不事后修改参考或阈值使某组胜出。

样本小，结果只能支持初步选择。若V2有明确收益，可再用更贴近实际的公开资料复核；如果只是128k带来收益而算法差异不明确，不能宣称V2算法优化成功。未经用户根据报告决定，网页/API继续默认V1。

## 7. 需要确认的执行范围

建议批准上述四份公开合成资料×四组、串行、每任务16次/总128次调用上限；包含先四组冒烟、保留所有失败和usage未知项，不包括归组、练习生成、部署或默认切换。若用户希望更低成本，可先仅执行一份跨章节资料的四组诊断，再决定是否扩样。
