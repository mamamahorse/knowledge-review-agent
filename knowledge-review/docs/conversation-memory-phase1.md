# 会话记忆第一阶段：实现、运行与边界

实现核对日期：2026-10-04。本页描述实际代码；长期方案见 conversation-memory-design.md。

## 一条消息如何运行

1. 浏览器选择或新建聊天，提交稳定的 `request_id`、完整用户输入、当前语言及本次资料范围。发送结果未确认时，浏览器保留原提交标识，重发仍对应同一轮。
2. 后端取得本聊天的非阻塞 OS 文件锁。在短事务中建立轮次并保存用户原话，再进行资料版本验证和上下文准备。已完成请求直接读回保存的结果；有不同的未完成轮次时返回 409。
3. `build_context()` 读取此会话已完成的对话。短聊天直接保留全部原话，长聊天组织摘要、近期完整轮次和相关早期原话。失败或跳过的输入仍在存档中，但没有虚构的助手消息，不加入已完成历史。
4. `run_agent()` 将背景绑定到本轮不可变 Source 快照、目录和可选焦点。模型在 `tool_choice=auto` 下决定是否调用 search_notes/read_source。只有搜索才加载 embedding；工具结果经过预算检查才加入可见资料。
5. 最终 `answer_question()` 使用同一个背景对象，另加入可见原文，发送 NoteAnswer 或严格模式的 SourceOnlyAnswer。结构化兼容机制保持原样；实际发送的资料范围决定引用权限。
6. 本地结构与引用验证通过后，短事务原子保存助手可见结果和 completed 状态。`attempt` 必须仍匹配，旧生成不能覆盖新轮次。失败保存可理解错误和 failed 状态，用户原话不丢失。

两个阶段不是相同的请求：Agent 有查资料工具与工具协议历史，最终阶段有答案 Schema 和实际可见原文。它们共享同一份历史/摘要/原话补回、当前语言、允许资料版本及选段，因此工具阶段的背景不会在最终回答时丢掉。历史装在明确标记为数据的用户上下文中，没有提升成系统指令。

## 为什么使用这些对象和表

| 模块 / 表 | 作用与取舍 |
| --- | --- |
| `conversation_store.py` / conversations | 稳定会话 ID、标题、UTC 创建/活动时间；与文档和练习的身份分开 |
| turns | 会话内递增 seq、request_id、running/failed/completed/cancelled、尝试标识、原请求、错误和上下文快照；便于去重、恢复和排序 |
| messages | 不可变用户原话、助手可见文本和完整显示用结果 JSON；每轮每种角色最多一条 |
| summaries | 当前有效摘要、递增版本、覆盖轮次、水位前缀指纹、结构化事项/证据 ID 和生成模型标识；可从原话重建，不替代原话 |
| `ContextBundle` | 两阶段共用的不可变背景视图；存档和本次模型可见内容分离 |
| `generation_budget.py` | 与本地 embedding 无关的生成请求预算和完整原文行裁剪 |

数据库为 `.data/conversations.sqlite3`；学习仍使用 `.data/practice.sqlite3`，向量缓存仍使用 `.data/embeddings.sqlite3`。没有更改现有数据库内容，聊天也不会创建学习事件或自动加入计划。当前无需新增向量数据库或 Agent 框架。

数据库旁的 `conversations-<聊天ID>.lock` 是生成互斥用的文件，不包含聊天正文。Windows 用 msvcrt，其他系统用 flock；进程退出后锁自动释放。读取历史时，若能取得锁且发现遗留 running，将其改为可重试的 failed；活跃生成期间读取不会误重置状态。不同聊天有独立的锁。网络等待、摘要生成和 embedding 都在 SQLite 写事务外。

同一聊天未完成的输入需重试或点击“跳过，保留原话”后再提交新消息，避免两轮生成乱序。跳过不删除输入，之后不能重开该轮，以免后来的历史顺序变化。重试可以使用当前语言，但沿用原问题和原资料范围；资料已修改时仍拒绝旧版本，需跳过并重新提交当前版本的请求。

## 摘要与早期原话

默认给历史留输入预算的 45%，并进一步扣除当前问题、资料目录、焦点、偏好、工具/Schema 和任务余量。完整已完成历史能容纳时，不额外调用摘要模型；超出时才处理早期前缀。

至少保留最近两个完整已完成轮次；预算宽裕时保留更多。摘要按完整轮次分批，每一批都检查完整摘要请求与 Schema 的预算。增量输入是有效旧摘要加新增原话。事项明确区分用户目标、用户决定、用户疑问、助手解释和重要例子；证据 ID 必须来自本次摘要可见原话或有效旧摘要。用户事项必须指向用户消息，助手解释必须指向助手消息。程序只验证归属与范围，不能证明概括忠实。

发布前在短事务中核对预期摘要版本和当前原话前缀指纹。追加新消息不破坏有效前缀；新摘要已发布或前缀不匹配时拒绝旧结果。失败不写空摘要；原话、有效旧摘要保留。若旧摘要加未覆盖原话仍无法安全容纳，当前轮次失败但保留输入，稍后可重试。

早期补回只使用当前会话：匹配当前问题和最近用户话题的英文/数字词、中文双字；重合度优先，同分再优先较近轮次，不按年龄淘汰。原话视图带消息 ID、角色、轮次、字符起止偏移和匹配原因，实际字符串从存档精确截取；不会拿归一化搜索文本冒充原话。已在近期窗口的消息不重复补回。该方法简单、可解释，但不能保证命中不同措辞的旧讨论，尚未实现语义召回或 Agent 历史读取工具。

摘要是下一次提交时同步维护的，没有后台队列；非常长的积累可能增加本次延迟。没有原话编辑、删除或摘要更正入口；未来加入这些功能时须扩展版本与失效规则。增量摘要可能漂移，证据指针和原话存档用于核对，当前还没有自动全量重建/语义忠实度评估。

## 生成预算

| 环境变量 | 未配置时的应用值 | 意义 |
| --- | --- | --- |
| LLM_CONTEXT_TOKENS | 32768 | 本应用采用的请求总窗口上限；请按实际服务和模型的可靠配置设置 |
| LLM_OUTPUT_TOKENS | 4096 | 预留输出空间，并用 max_tokens 限制生成；推理模型可能将内部推理计入此值 |
| LLM_SAFETY_TOKENS | 2048 | 估计差异与服务协议的安全余量 |

这些默认值不是从模型名称推导的真实容量。无明确配置时诊断会标注 application fallback / service capacity unverified。当前兼容接口没有可靠的统一计数能力，也没有已核实匹配生成模型的本地 tokenizer，所以使用序列化请求的 UTF-8 字节数加消息/协议余量作为保守 token 估计，另留安全空间。这通常明显多算普通 BPE 文本，但不能保证未知服务的计数方式；服务容量小于应用上限时仍可能拒绝请求。

检查对象包括系统内容、当前问题、语言偏好、历史/摘要/召回、目录/焦点/资料、工具定义、助手工具调用与工具结果、原生结构化 Schema（由已安装 SDK 展开）、兼容结果工具与请求选项。实际每次 Agent 请求、最终请求、摘要请求和兼容回退请求都检查，不用 multilingual-e5-small 的 tokenizer。

裁剪顺序：提前缩小历史份额并按压力摘要；早期原话补回在剩余预算内选择；工具结果不足以容纳时限制可选资料；最终阶段再次按包含 Schema 的预算缩小补充资料。资料只能按完整原文行保留连续前缀或丢弃整个片段，可引用行号随实际发送范围缩小。显式选段及其邻近上下文、当前问题不会偷偷截断；单条必要内容过大时给出预算错误并保留输入。CLI 全文模式超预算也报错，不悄悄变成 RAG。

轮次上下文快照保存历史消息 ID、摘要版本/覆盖水位、原话补回偏移、本轮资料版本/焦点、实际请求预算估计和最终可引用范围。没有保存认证头或密钥，也没有保存隐藏推理；资料的完整历史版本尚未存档，快照不是模型输出可完全重现的保证。

## 接口与运行

| 接口 | 当前作用 |
| --- | --- |
| POST /api/conversations | 新建聊天 |
| GET /api/conversations | 按活动时间列出聊天 |
| PATCH /api/conversations/{id} | 重命名 |
| GET /api/conversations/{id}/messages?after_seq=0&limit=100 | 逐轮分页恢复完整用户/助手消息及状态；next_cursor 表示下页 |
| POST /api/conversations/{id}/turns | 保存输入并生成；携带 request_id 与现有 AskRequest 字段 |
| POST /api/conversations/{id}/turns/{turn_id}/retry | 重试同一轮，可传当前 response_language；已完成时直接返回 |
| POST /api/conversations/{id}/turns/{turn_id}/skip | 跳过 failed 输入，保留原话 |
| GET /api/conversations/{id}/summary | 当前摘要版本、水位及证据指针 |

生成失败的持久会话接口返回保存后的 failed 轮次（HTTP 200），UI 必须查看 status；身份不存在返回 404，并发或幂等冲突返回 409，请求结构不合法返回 422。旧 `/api/ask` 仍是非持久一次问答，CLI 也不自动创建聊天。

```powershell
Set-Location 'E:\agentic project\knowledge-review'
.\.venv\Scripts\python.exe web_app.py
# 浏览器打开 http://127.0.0.1:8765/

.\.venv\Scripts\python.exe -m unittest test_conversations -v
.\.venv\Scripts\python.exe -m unittest discover -v
.\.venv\Scripts\python.exe -m pip check
node --check web/static/app.js
node --check web/static/learning.js
```

使用既有 .venv 和模型配置，不需安装新依赖。若服务已启动，需要重启加载这次 Python 改动，并刷新网页加载新脚本。
