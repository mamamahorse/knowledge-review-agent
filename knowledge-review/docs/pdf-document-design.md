# Markdown 与 PDF 统一文档设计

日期：2026-10-15。本文记录用户讨论后授权的设计，以及分阶段落地边界。实现状态以末尾验收记录和代码为准，不能把目标能力当作已经实现。

## 目标与数据流

Markdown 和 PDF 都转换为项目自己的 Document / ContentBlock / Asset，随后生成可追溯的文本视图，复用现有 Embedding + BM25 + RRF、问答、出题及学习链路。保留原始文件和视觉证据；来源仍受当前资料范围、不可变版本、实际可见内容约束。

PDF → 常规结构解析 → 按页质量检查 → 异常页有界 VLM 转写 → 统一结构与稳定文本视图 → 结构感知检索 → 按需补读表格或视觉资源。

## 统一契约

- Document：格式、原文件哈希、解析配置/版本、文本视图、内容块、资源、页数和质量报告。现有 document_id 继续表示资料库身份；source_id 表示实际可引用的快照。
- ContentBlock：版本内唯一 ID、类型、顺序、章节路径、文本视图行范围、原始位置列表、资源引用和提取方法。支持 heading/paragraph/list/code/table/formula/figure。内容块与检索 Chunk 分开。
- Asset：资源 ID、类型、原始文件或派生页面/区域、页码、区域及内容身份。原始 PDF 是视觉事实来源；页面和区域可从固定原文件按需渲染。
- Location：Markdown 使用原始行号，PDF 使用从 1 开始的物理页码与左上原点页面坐标。允许多个位置和空 bbox；没有的坐标不能由模型猜测。文本视图行号不称为 PDF 原文行号。
- 空值表示不适用或未知；身份、类型、提取方法和状态不得缺失。质量状态描述已发现的问题，不提供未经校准的“正确率”。

Markdown 文本、旧 source_id、行号和既有块算法尽量保持。新增元数据按需构造，不改写用户原文件。PDF 的 source_id 同时绑定原文件内容、解析配置和最终结构；重新解析不得让旧引用悄悄跳到新结果。

## 解析与质量路由

Docling 负责层级、阅读顺序和表格结构，PyMuPDF 负责页面信息、辅助文本检查、页面/区域渲染。Docling 作为可选重依赖隔离，不在普通请求中隐式下载模型；依赖/模型未就绪时显式报告，基础 PyMuPDF 路线应标注能力差异。

不自建 OCR 系统。是否使用 Docling 内置 OCR 是显式配置，与是否为扫描件不直接绑定。先用现有文字、布局和表格信息；低文字提取量、乱码、重叠/多栏可疑、结构缺失等产生页级 issues。封面、空白页和纯图页不能仅因字少便断言失败。规则是可疑检测，不保证语义完整。

VLM 默认只处理可疑页面，限定页面数、像素数、输出和尝试次数；转写与解释分开。看不清的内容保留 unresolved，不编造原文。失败保留常规结果及错误类型，文档允许 partial，整份 PDF 仅作为未来受预算约束的特殊路径。

## 表格与图片分块

完整表格和图片保留为父内容块。检索子块保留 parent_block_id、行列范围和原始位置。小表格整体保留；长表按完整行组切分，每组携带可追溯的表头、表题、单位和相关脚注。超宽表按列组时必须保留行标识；未可靠识别的合并单元格和跨页续表不强行还原。

Embedding、检索结果、模型输入预算三处都必须保护结构，不能在后续再次按普通行裁掉表头。重复表头属于真实原文的独立可见范围，不能把非连续范围伪装成连续原文。检索命中后按问题和预算补读父对象；整表最大值/总和/比较不能把 top-k 行当成完整数据。

大图保留整图，提供图注、章节、邻近正文和页码等检索线索。查看时可用全局概览加高分辨率区域，裁剪保留图例及连接关系；纯图片没有文字入口时存在漏检风险。第一版不创建原生视觉向量索引，但统一结构预留独立视觉检索入口；后续按“没找到图”和“找到但没读懂”分别评测。

## 证据与存储

PDF 原件与解析快照保存在受管理目录；解析输出在发布前完整写好并原子替换，不能每次阅读重跑解析。保存失败/部分状态、解析方法及版本。原文件替换与重新解析均创建新快照，旧题和回答绑定旧版本。

沿用实际可见文本范围校验，页面/资源定位只是导航，不能凭“文件存在”扩大引用权限。VLM 视觉观察保存独立的有来源结果，并参与最终回答输入及预算；未发送的原图内容不能自动成为最终模型可引用证据。

不新增外部服务框架或向量数据库，不改现有学习调度，不自动加入学习计划。资料移除、版本变化和迟到任务仍沿用当前权限复核规则。

## 实施顺序与验收

1. 统一结构、Markdown 适配、表格结构保护及旧引用回归。
2. PDF 常规解析、快照缓存、网页导入/阅读、页码定位与原图读取，跑通已有检索和出题服务。
3. 有界 VLM 转写与失败状态、按需视觉证据。真实调用与模拟测试分别报告。
4. 根据真实漏检样例决定是否增加视觉向量分支，再与文本路排名融合；不同模型向量不混算。

验收覆盖普通文本、多页、多栏可疑、表格、图片、空白/扫描、解析失败、失效版本和 Markdown 回归。使用合成资料与隔离目录，不拿真实用户资料做云端测试，不改正式学习记录。

## 本批实现与验证记录

### 已实现的纵向链路

基础路径使用 PyMuPDF，已安装并实测版本 1.27.2.3。网页支持混合导入 Markdown/PDF、提取文本阅读、原始页面展开、页码/区域引用、同格式文件替换及重新解析；CLI 的普通预览、分块和既有检索入口接受 PDF。PDF 现限制为 20 MB、200 页，不接受需要密码的文件。解析提示按页面显示，部分结果不伪装成完整成功。

现有问答、出题与聊天出题快照保存 PDF 结构。纯图导航标签不作为文字出题依据；文字出题当前基于已提取/转写的文本，不包含一个独立的视觉出题 Agent。旧版本原件保留，资料移除撤销当前 API 访问资格，不物理删除历史原件。

长表格按完整文本行建立检索子块，索引输入补入原始表头；给模型的表头是独立、真实的原文范围，引用权限不跨越未发送的中间行。选段、按行读取、检索工具和最终模型预算均保护这些依赖。继续开发后还补入同页、位置相邻且有长度限制的表题/说明与注释/单位/来源原文；邻近关系是上下文线索，不是程序对单位含义的语义证明。

新增 read_table(source_id, block_id, row_start, row_end)，按从 1 开始、不含表头的数据行读取；返回 total_extracted_rows 和 complete_extracted_table，并补齐表头和说明。每次最多 200 个数据行，实际文字范围还受原有读取与生成预算限制。最终模型输入还会按预算裁剪后的实际可见原文范围重新计算表头、数据行和整表覆盖，不能沿用裁剪前的完整标记。覆盖标记只针对已提取的表，不证明原 PDF 提取完整。当前没有通用的列组拆分、合并单元格恢复、自动续表合并或精确整表计算工具；遇到缺失单元格标记核对，完整表格数据与原图仍保留。

### 模块变化与理由

| 模块 | 改变与原因 |
| --- | --- |
| document_model.py / sources.py | 提供统一结构、可空原始位置和序列化快照；保留 Markdown 文字和旧身份算法，PDF 身份绑定原件和最终解析内容 |
| pdf_parser.py | 提取表格/文字、检测可疑页面、缓存不可变结果、按原件哈希渲染页面和区域；从原 PDF 渲染可保留矢量图，避免只保存嵌入图片导致漏图 |
| chunking.py / embeddings.py | 原始内容块与检索窗口分开，长表格携带父身份及真实表头位置；单个超长行保持完整，通过编码窗口处理而非裁掉字符 |
| knowledge_tools.py / generation_budget.py | 搜索与读取返回独立的表头范围，预算不足时舍弃完整结构组；不能只剩数值而缺少列含义 |
| pdf_vision.py / agent_loop.py / model_client.py / answers.py | 提供有界转写与 inspect_visual，成功观察进入最终请求和程序存档；asset_id 引用必须匹配成功回执，不能只让前阶段看到解释 |
| library_store.py / practice_store.py | 增加可空结构快照列并保留旧行；练习恢复不依赖新版 PDF 的相同行号 |
| web_app.py / web/ | 导入时解析并持久保存，阅读时复用；替换和重新解析用既有 revision 比较发布，防止迟到任务覆盖新版本；PDF 引用展示页码与原图 |

### 可选解析与视觉配置

基础依赖随 requirements.txt 安装；已有环境可单独安装 requirements-pdf.txt。Docling 适配已编写，但本次没有安装 Docling 的重依赖或下载/运行其模型，不能称其结构提取质量已验收。启用方式为安装 requirements-docling.txt、设置 PDF_PARSER=docling 及已准备好的 DOCLING_ARTIFACTS_PATH；PDF_DO_OCR 仅控制 Docling 内置 OCR。Docling 执行失败时保留带明确失败标记的基础候选。

VLM 使用既有 Chat Completions 兼容连接方式。按用户后续明确要求，默认复用 LLM_MODEL/LLM_API_KEY/LLM_BASE_URL；VLM_MODEL/VLM_API_KEY/VLM_BASE_URL 各自的非空配置可独立覆盖对应聊天字段，空字符串也回退。没有修改用户 .env 或替用户更换模型，实际默认模型仍为原先的 deepseek-flash。

不按模型名称推断能力，也不在普通预览中额外发预探测请求。实际图片请求成功时记录支持；明确的图片输入拒绝才记为 unsupported，同一进程内按服务地址、模型和凭据指纹隔离，后续不重复请求。换配置/重启后可重新尝试。超时、连接、401/403、429、500、无效图像和结构化输出协议不兼容均不能误记为模型不支持图片；普通文本功能继续可用。

有可用聊天或视觉模型连接时，问答 Agent 可按需调用 inspect_visual。查看区域时提供整页和局部两张图，单图最多约 400 万像素；最终回答使用有归属的模型观察，保留局限说明。图片预算使用明确标注的应用估计，不能当成服务真实计费或 token 数。

导入时视觉转写另需 PDF_VLM_ENABLED=1，最多处理 3 个异常页；其余页面保留未解决状态。结构化协议兼容探测可能产生额外 HTTP 请求，3 页是逻辑任务上限。保留常规候选、VLM 返回候选及最终采用内容；截断、异常和无法辨认内容保留失败或 partial 状态，普通阅读不会隐式重试。调整模型或解析配置后通过“重新解析 PDF”创建新快照。
